# 시연 영상 컷 목록 — 운전 연수 어시스턴트 (후면 직각 주차)

초안(2026-09-26). 제출물 ③ "시연 영상 — 3D 에뮬레이터 연동 동작 녹화"용. **길이·해상도·형식·자막 허용 여부는 주최 공지를 확인**한다(`docs/00_hackathon_overview.md` 최종자료 제출 페이지). 조작 순서와 시각은 `docs/05_demo_script.md`(실측 103초) 가 원본이고, 이 문서는 그것을 영상으로 옮길 때의 컷·자막·녹화 절차다.

## 두 가지 판

| 판 | 어디서 | 용도 | 조작 |
|---|---|---|---|
| **A. 사내 판(제출용)** | 사내 3D 에뮬 + Real VSS(**Hybrid** — 실물에서 안 오는 키만 시뮬레이션) | 제출 | 속도·도어는 Signal Simulator 로. 시연 패널은 보이지만 **실물이 주는 키(속도·도어)에는 먹지 않는다**. 조향각·기어가 실물에 없으면 패널의 시나리오가 채운다 |
| **B. 외부 판(예비·발표 삽입용)** | 외부 에뮬 `CSTDe_API_34`, 기본 Fake 빌드 | 사내 녹화가 막힐 때의 보험, 발표 4번 장 | 화면 오른쪽 시연 패널(잘한/못한 주차·정차·출발·문 열기/닫기) |

**B 를 먼저 찍어 둔다.** A 는 이관 후 같은 컷 목록으로 다시 찍는다 — 배지의 `실신호 N` 이 올라간 화면이 A 판의 핵심 증거다.

편집 원칙
- **앱 음성(TTS)이 주인공**이다. 나레이션을 얹는다면 앱 음성이 없는 구간(0·1·3·8·11·12)에만. 음성은 `ko-kr-x-kob-network`(기본값) — 녹화는 **인터넷이 연결된 상태**에서.
- 배속은 컷 5 의 보정 구간과 컷 8 의 곧게 후진 구간에만. 힌트가 나오는 순간(4·6)·Done·Report 는 **원속도** — 음성과 어긋나면 안 된다.
- 자막은 한 줄, 신호 이름은 영문 그대로(`Vehicle.Speed`, `SteeringWheel.Angle`, `SelectedGear`, `Door.IsOpen`) — 심사자가 VSS 사용을 바로 알아보게.
- 시연 패널은 가리지 않는다 — 시뮬레이션으로 조작하고 있음을 숨기지 않는다. 배지도 같은 이유로 자른 컷에 반드시 남긴다. A 판에서는 Signal Simulator 창을 화면 한쪽에 같이 담으면 "실제 차량 신호로 움직인다"는 증거가 된다.
- 잘라도 되는 것: 컷 8 을 통째로(1회차만으로 1분 30초). 자르면 안 되는 것: 컷 6(힌트 3종의 마지막 둘)·10(배지).

## 녹화 절차 — B. 외부 판

```powershell
.\gradlew.bat assembleDebug                      # 기본 -PdemoSpeed=1.0 (실시간). 모자라면 1.5
adb -s emulator-5554 install -r automotive\build\outputs\apk\debug\automotive-debug.apk
```
```bash
bash tools/emu_flow.sh <출력폴더>                 # 리허설: "result: PASS", "clashes: 0"
```

- 화면만: `adb -s emulator-5554 shell screenrecord --display-id 4619827259835644672 --time-limit 180 /sdcard/demo.mp4` → `adb pull`. **소리는 담기지 않는다**, 한 번에 최대 180초. 끝낼 때는 `adb shell pkill -INT screenrecord`(에뮬 안의 pkill 은 된다 — PC 쪽 Git Bash 의 pkill 이 안 되는 것).
  - 함정 ①: 화면이 멈춰 있으면 프레임을 남기지 않는다(가변 프레임). 정지 화면을 뽑을 때 `ffmpeg -ss <시각>` 은 다음에 바뀐 프레임을 준다 — `ffprobe -show_entries frame=pts_time` 로 실제 프레임 시각을 본다.
  - 함정 ②: 녹화 중 `screencap` 병행은 파일이 남지 않았다(16번 경험). 프레임은 영상에서 뽑는다.
- 소리까지: PC 화면 녹화 도구(Windows 게임 바 `Win+Alt+R`, OBS 등)로 에뮬 창을 녹화. 에뮬 미디어 볼륨 확인. 발표·제출용은 이쪽.
- 녹화는 **사람이 직접 누른다**. `emu_flow.sh` 는 탭마다 화면 덤프에 몇 초씩 써서 영상이 늘어진다(스크립트 103초 → 사람이 누르면 약 90초). 말·자막 시간이 모자라면 패널 **정차**로 멈춘다.
- 앱을 강제 종료 후 다시 열어 `Setup` 에서 시작(진행 기록은 인메모리 — 새로 시작하면 "처음 하는 과제"라 가이드 모드를 제안한다. 영상은 **힌트**를 고른다).

## 녹화 절차 — A. 사내 판

- 이관: `docs/06_inhouse_migration.md`. 빌드가 되면 먼저 Signal Simulator 로 `Vehicle.Speed`=0 / 운전석 도어 Open 이 리포트를 여는지부터 확인(대본 "사고 대응").
- 조향각·기어·벨트·뒤 거리 신호가 Signal Simulator 에 있으면 그것으로 조작하고 컷 3 자막을 "실신호"로 바꾼다. 없으면 Hybrid 가 시나리오로 채운다 — 배지의 `시뮬레이션 N` 이 그 사실을 말한다.
- 컷 목록은 같다. 조작 열의 **정차/문 열기**를 Signal Simulator 조작으로 바꾼다.
- 사내에서 찍은 영상·캡처는 이 저장소에 넣지 않는다(정책). 배지의 숫자만 메모해 와 발표 8·11번 장을 고친다.

## 확인하지 못한 것

- 주최가 요구하는 영상 길이·형식. 위 길이는 시연 대본의 실측에서 나온 것이지 규정이 아니다.
- 사람이 직접 누를 때의 실제 길이(약 90초 추정) — 첫 녹화에서 재서 이 표의 "길이" 열을 고친다.
- 음성과 화면 전환의 어긋남(회차 멘트가 길면 `Done` 화면이 먼저 뜬다) — 귀로 확인.
