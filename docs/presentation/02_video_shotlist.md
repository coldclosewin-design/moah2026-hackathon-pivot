편집 원칙
- **앱 음성(TTS)이 주인공**이다. 나레이션을 얹는다면 앱 음성이 없는 구간(0·1·3·8·10b·11·12)에만. 음성은 `ko-kr-x-kob-network`(기본값) — 녹화는 **인터넷이 연결된 상태**에서.
- 배속은 컷 5 의 보정 구간과 컷 8 의 곧게 후진 구간에만. 힌트가 나오는 순간(4·6)·Done 궤적 재생(7·9)·Report 는 **원속도** — 음성과 어긋나면 안 된다.
- 자막은 한 줄, 신호 이름은 영문 그대로(`Vehicle.Speed`, `SteeringWheel.Angle`, `SelectedGear`, `Door.IsOpen`) — 심사자가 VSS 사용을 바로 알아보게.
- `시연` 을 눌러 시나리오를 고르는 장면은 **자르지 않는다** — 시뮬레이션으로 조작하고 있음을 숨기지 않는다(패널은 고르면 접히므로 화면을 가리지 않는다). 배지도 같은 이유로 자른 컷에 반드시 남긴다. A 판에서는 Signal Simulator 창을 화면 한쪽에 같이 담으면 "실제 차량 신호로 움직인다"는 증거가 된다.
- 운전자 문장에 숫자가 보이거나 `Done` 에 판정 네 줄이 없으면 옛 빌드다(라운드 3 이전 / 라운드 12 이전) — 다시 찍는다. 숫자는 Report **자세히 보기**·진단서 컷에만 있어야 한다.
- 잘라도 되는 것: 컷 8 을 통째로(1회차만으로 1분 30초), 컷 10b. 자르면 안 되는 것: 컷 6(힌트 3종의 마지막 둘)·7(궤적 + 판정 네 줄 + 추정 캡션)·10(배지).

## 녹화 절차 — B. 외부 판

```powershell
.\gradlew.bat assembleDebug                      # 기본 -PdemoSpeed=1.0 (실시간). 모자라면 1.5. -PdemoPanel=false 는 쓰지 않는다(시나리오를 못 돌린다)
adb -s emulator-5554 install -r automotive\build\outputs\apk\debug\automotive-debug.apk
```
```bash
RESERVE=1 bash tools/emu_flow.sh <출력폴더>       # 리허설: "result: PASS", "clashes: 0". RECORD=/sdcard/demo.mp4 를 주면 스크립트가 녹화까지(소리 없음)
```

- 화면만: `RECORD=/sdcard/demo.mp4 RESERVE=1 bash tools/emu_flow.sh <폴더>` → `<폴더>/demo.mp4`(1920×1080 · 6 Mbps · time-limit 0, 9/29 부터). 수동이면 `MSYS_NO_PATHCONV=1 adb -s emulator-5554 shell screenrecord --time-limit 0 /sdcard/demo.mp4` → pull. **소리는 담기지 않는다.** 끝낼 때는 `adb shell pkill -INT screenrecord`(에뮬 안의 pkill 은 된다 — PC 쪽 Git Bash 의 pkill 이 안 되는 것).
  - 함정 ①: 화면이 멈춰 있으면 프레임을 남기지 않는다(가변 프레임). 정지 화면을 뽑을 때 `ffmpeg -ss <시각>` 은 다음에 바뀐 프레임을 준다 — `ffprobe -show_entries frame=pts_time` 로 실제 프레임 시각을 본다.
  - 함정 ②: 녹화 중 `screencap` 병행은 파일이 남지 않았다(16번 경험). 프레임은 영상에서 뽑는다.
  - 함정 ③: `/sdcard` 경로는 `MSYS_NO_PATHCONV=1` 없이는 `C:/Program Files/Git/sdcard` 로 변환된다(9/27).
  - 함정 ④: 녹화 부하가 코루틴 순서를 바꿔 **경합을 드러낸 적이 있다**(9/27 PR #19). 녹화본에서 `Done` 이 안 뜨거나 `한 번 더` 가 없으면 스크립트 문제가 아니라 상태기계를 의심한다.
  - 함정 ⑤: 녹화 부하로 회차 1 이 시간 감점 경계(70 s)를 넘으면 숙련 58 — 판정·조언은 같아 영상엔 지장 없지만 `자세히 보기` 숫자가 달라진다. 거슬리면 다시.
- 소리까지: PC 화면 녹화 도구(Windows 게임 바 `Win+Alt+R`, OBS 등)로 에뮬 창을 녹화. 에뮬 미디어 볼륨 확인. 발표·제출용은 이쪽.
- 녹화는 **사람이 직접 누른다**. `emu_flow.sh` 는 탭마다 화면 덤프에 몇 초씩 써서 영상이 늘어진다(스크립트 111 s → 사람이 누르면 약 100 s 추정). 말·자막 시간이 모자라면 `시연` → **정차**로 멈춘다.
- 앱을 강제 종료 후 다시 열어 `Setup` 에서 예약부터(대본 "준비"). 진행 기록은 인메모리 — 새로 시작하면 "처음 하는 과제"라 가이드 모드를 제안한다. 영상은 **힌트**를 고른다.

## 녹화 절차 — A. 사내 판

- 이관·검증: `docs/06_inhouse_migration.md`·`docs/07` §3(`inhouse_check.sh` 합격 뒤). 먼저 Signal Simulator 로 `Vehicle.Speed`=0 / 운전석 도어 Open 이 리포트를 여는지부터 확인(대본 "사고 대응").
- 패널 `AI 연결` 로 Copilot 로그인(`AI 코치 · 연결됨`) — 회차 멘트·총평이 Cloud 문장이 된다. 안 되면 시드 문장으로 폴백, 영상엔 지장 없다.
- 조향각·기어·벨트·뒤 거리 신호가 Signal Simulator 에 있으면 그것으로 조작하고 컷 3 자막을 "실신호"로 바꾼다. 없으면 Hybrid 가 시나리오로 채운다 — 배지의 `시뮬레이션 N` 이 그 사실을 말한다(10/2 실측은 시뮬 1).
- 컷 목록은 같다. 조작 열의 **정차/문 열기**를 Signal Simulator 조작으로 바꾼다. 컷 7·9 의 방향 판정이 실차 조향각으로 말이 안 되면(NEXT 확인 항목 ⑥) 그 줄은 `—`(미측정)로 나온다 — 그대로 찍고 메모.
- 사내에서 찍은 영상·캡처는 이 저장소에 넣지 않는다(정책). 배지의 숫자만 메모해 와 발표 8·9·11번 장을 고친다.

## 확인하지 못한 것

- 주최가 요구하는 영상 길이·형식. 위 길이는 시연 대본의 실측에서 나온 것이지 규정이 아니다.
