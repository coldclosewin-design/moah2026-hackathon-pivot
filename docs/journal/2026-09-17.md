## 결정과 이유

- **결정**: 시연은 에뮬 1대. **대안**: 그룹 드라이브(메모 4·5)를 위한 다중 차량. **이유**: 1인 개발·기간 안에 서버·2대 에뮬은 무리. B계열 제외.
- **결정**: 콘텐츠는 AI 생성. **대안**: 주민/사장님 업로드 구조. **이유**: 작성자 앱+서버는 범위 초과. "주민 데이터"는 확장 스토리로만.
- **결정**: 결합안(01)을 택하되 **04(미스터리 드라이브)를 1주차 MVP**로. **이유**: 두 후보는 상태기계와 포트가 같다. 1주차 결과물이 그 자체로 제출 가능하고, 시간이 모자라면 뒤에서부터 잘라낸다.
- **결정**: 포트 4개를 전부 Fake로 두고 시작. **이유**: 인터넷·키 없이 전체 흐름이 도는 상태를 먼저 만들면 실구현은 하나씩 갈아끼우기만 하면 된다. 사내 네트워크가 불안해도 시연이 성립.
- **결정**: Gift Drive 확장 채택. **대안**: Mood Drive 유지. **이유**: 맨 끝에 붙어 있던 "지인 메모리"가 여정 전체의 이유가 되면서 심사 스토리가 "AI가 아무 데나 골라주는 앱"에서 "사람의 마음을 차가 전달하는 앱"으로 바뀐다. 커피 픽업·주차 안내가 정거장으로 자연스럽게 흡수된다. AI 점수는 5→4로 내려가지만 편의/안전 설득력이 4→5. **되돌릴 조건**: 심사가 "AI 활용도"를 최우선으로 본다는 정보가 나오면 AI 추천을 기본으로 되돌린다(폴백이 남아 있어 코드는 그대로).
- **결정**: 실시간 "함께" 기능(위치 공유·채팅)은 제외. **이유**: 서버·다중 사용자. "함께"의 느낌은 정거장마다 재생되는 지인의 목소리로 충분.
- **결정**: 정거장 간 전환은 "다음 장소로" 버튼(정차 상태). **대안**: 도어 닫힘·기어 D 자동 감지. **이유**: 기어 신호 경로가 사내 확인 전. INTEGRATION.md에 기록.
- **결정**: 선물이 여러 개 맞을 때 **가장 먼 곳**을 고른다. **이유**: 주어진 시간을 채우는 "떠나는" 느낌. 시연 목적지(판교 현대백화점)가 자연스럽게 선택된다.

## 막힌 것과 해결

- **JVM 테스트에서 상태기계가 Planning에서 멈춤** → `android.util.Log`가 목킹되지 않아 예외로 코루틴 종료 → `testOptions.unitTests.isReturnDefaultValues = true` → **교훈**: 상태기계에 Log를 넣었으면 테스트 옵션부터.
- **도착 대기가 위치 스트림 종료에 묶여 정차 시 교착** → "남은 거리 collect가 끝난 뒤 도착 대기"로 짰는데 차가 서면 스트림이 안 끝남 → 위치 수집을 자식 코루틴으로 띄우고 `arrivalSignal.first { it }`로 대기, 도착 시 자식 취소 → **교훈**: 두 신호(거리, 차량 상태)를 기다릴 땐 순차가 아니라 병렬 + 신호.
- **예외로 collect를 빠져나오는 설계** → 앱 스코프의 uncaught exception은 크래시 → 신호(StateFlow)로 교체.
- **같은 GitHub 계정이라 PR approve 불가** → `gh pr review --approve`가 거부, 자동 모드 분류기도 머지를 막음 → 리뷰 결과는 코멘트로 남기고 머지는 사용자가 수동 → **교훈**: 1인 팀에서 "리뷰어 = 작성자 계정"이면 approve 대신 코멘트 규약을 정해둔다.
- **(2026-09-18 정정)** 아래 "자동 시연 스크립트" 항목의 원인 분석은 불완전했다. 다음 날 확인해 보니 이 환경의 `pkill` 은 동작하지 않아(exit 127) 이날 "중지했다"고 여긴 스크립트들이 실제로는 겹쳐 돌고 있었고, 주행 화면에서는 `uiautomator dump` 가 실패해 낡은 파일을 읽고 있었다. 아래 네 가지 교훈은 각각 사실이지만, 반복 실패의 큰 원인은 이 두 가지였을 가능성이 높다. 상세: [2026-09-18](2026-09-18.md).
- **자동 시연 스크립트 3번 실패** → (1) `timeout` 아래에서 `adb shell uiautomator dump`가 stdin을 기다리며 멈춤 → `</dev/null` (2) 경로 변환을 끈 상태라 `adb pull`이 `/c/...`를 못 읽음 → `cygpath -w` (3) `text="정차"` 접두 매칭이 "정차 후 문을 열면…" 문장을 먼저 잡음 → 정확 일치 (4) 앱이 그려지기 전 첫 덤프 → 라벨 탐색 재시도 → **교훈**: 에뮬 자동화는 "stdin 닫기, Windows 경로, 정확 매칭, 재시도" 네 가지가 기본값.
- **Codex의 도착 화면이 정거장을 모름** → 상태기계가 먼저 바뀌어 "다음 장소로" 버튼이 없으면 main에서 2정거장을 못 감 → Claude가 최소 버튼만 `[cross]` 표시로 넣고, 정식 디자인은 핸드오프 → **교훈**: 소유권 경계를 넘을 땐 "최소·표시·후속 핸드오프" 세 가지를 지킨다.
