## 한 일

- **(포트)** `GpsLocationPort`: Android `LocationManager`(GPS_PROVIDER)만 사용, Play services 의존 없음. 권한이 없거나 제공자가 꺼져 있으면 기존 `FakeLocationPort`(속도 적분)로 자동 폴백. (`dcaddcc`)

- **(검증)** 서초→운중동 직선 40포인트를 `adb emu geo fix`로 1.5초 간격 주입 → 첫 정거장 공개 → 정차·문 열기 → 쿠폰 카드. 로그에 `GPS updates started`, 총거리 10.5 km가 GPS 출발지 기준으로 계산됨. (`docs/screenshots/gps-01-reveal.png`, `gps-02-arrival.png`)

## 결정과 이유

- **결정**: GPS 포트를 Play services(FusedLocation) 대신 `LocationManager`로. **이유**: 사내 에뮬에 GMS가 있는지 미확인. 플랫폼 API면 어디서든 컴파일·동작. **되돌릴 조건**: 사내 에뮬에 GMS가 확인되고 정확도가 문제일 때.
- **결정**: 폴백을 "생성 시점"이 아니라 **호출 시점**(`observeRemaining`마다)에 판단. **이유**: 런타임 권한은 앱 시작 후에 허용될 수 있다. 첫 여정은 Fake, 둘째 여정은 GPS로 자연스럽게 바뀐다.
- **결정**: 기본값은 여전히 Fake. **이유**: 외부 시연은 시간 압축(배율 10)이 필요하고, 사내 3D 에뮬이 GPS를 주는지 모른다. 플래그 하나로 바꾼다.

### 결정과 이유

- **결정**: 주문 상태를 시간이 아니라 **남은 거리(ETA)**로 전이. **대안**: 타이머. **이유**: 실제 제휴 API 가 생겨도 앱이 할 일(ETA 보고)은 같다. 시연에서도 차가 서면 상태가 멈춰 자연스럽다.
- **결정**: 실행 여부의 기준을 프로세스 이름 매칭에서 **잠금 디렉터리 + PID 파일**로. **이유**: 아래 삽질 참고. 검사 명령 자신이 패턴에 걸려 오탐이 두 번 났다.
- **결정**: 여정의 시작·진행 판정을 화면 텍스트에서 **앱 로그**로. **이유**: 주행 화면은 덤프 자체가 안 된다.

### 막힌 것과 해결 (오늘의 핵심)

- **에뮬이 꺼진 줄 모르고 설치+스크립트 실행을 한 명령에 묶음** → 설치는 실패했는데 스크립트는 떠 버림 → "설치가 Success 일 때만 실행" 조건 추가.
- **그 스크립트를 "멈췄다"고 보고했지만 멈추지 못했음** → 이 환경의 `pkill` 은 없는 바이너리를 부르는 래퍼 함수라 exit 127. 오류를 `2>/dev/null` 로 버려서 몰랐고, 확인에 쓴 `ps -W | grep` 은 인자를 보여주지 않아 애초에 검출 불가능한 방법이었다 → 그 인스턴스가 에뮬이 뜬 뒤 되살아나 두 번째 실행과 **동시에** 돌았다. 증거: uiautomator "already registered" 충돌 40건, 스크립트가 누르지 않은 버튼이 눌린 흔적, 정차 상태인데 진행된 구간 → **그 실행은 오염된 검증으로 폐기**하고 다시 돌렸다.
- **"시작 탭이 씹힌다"는 관찰** → 처음엔 Compose 재구성 타이밍으로 추정, 동시 실행을 발견하고는 그 탓으로 돌림. **둘 다 틀렸다.** 단일 인스턴스에서도 재현돼 직접 조사 → 주행 화면은 0.5초마다 갱신돼 `uiautomator dump` 가 "could not get idle state" 로 실패하고 파일을 만들지 않는데, 스크립트가 실패를 무시하고 **예전 덤프 파일**을 읽었다. 앱은 첫 탭에 정상 시작했다(앱 로그가 증거). 앱 버그가 아니라 측정 도구의 결함이었다.
- **교훈**: (1) 오류 출력을 버린 명령의 성공을 보고하지 않는다. (2) "멈췄다/없다"는 확인은 그 방법이 애초에 검출 가능한지부터 본다. (3) 검증 도구가 말해주는 것과 시스템이 말해주는 것(로그)이 다르면 로그가 기준이다. (4) 추정은 추정이라고 쓰고, 틀리면 일지에서 정정한다(9/17 항목 정정함).

| 음성 퀄리티 낮음 | **조사 + 선택지 제공**. 에뮬의 한국어 음성은 로컬 4·네트워크 4종, API 상 품질 값은 전부 같다(400) → 코드로는 더 나은 것을 고를 수 없다. `-PttsVoice` 추가, 네트워크 음성 빌드를 에뮬에 설치해 **사용자가 듣고 결정**. 부족하면 시드 문장 사전 녹음(뉴럴 TTS) |
| 도착·접근을 글이 아니라 2D/3D 지도 위의 움직임으로 | **방식 결정 + 데이터 기반 완료 + Codex 핸드오프**. 자체 의사-3D(Canvas) — 아래 결정 참고 |
| D 구성에 A안(또는 classic) 느낌을 입혀 보고 싶다 | **미리보기 제공 → 결정**. 어느 쪽인지 모호해 두 스킨을 다 만들어 캡처 + 에뮬의 전환 버튼으로 제시 → 사용자가 **oneword** 선택 → 지도 핸드오프 1부에 포함 |

### 결정과 이유

- **결정**: 지도는 Google Maps SDK 가 아니라 **자체 의사-3D**. **대안**: Maps SDK(3D 기울임), 둘 다. **이유**: Maps 는 API 키·Play services·네트워크·새 Gradle 의존성이 필요하고 사내에서 되는지 외부에서 확인할 수 없다. 그리고 **실제 지도는 숨긴 목적지를 지리로 누설한다**(지명이 그대로 보인다). 자체 지도는 연출을 완전히 통제한다. 사용자 선택.
- **결정**: 화면에는 `Route`(전체 좌표)가 아니라 **상태기계가 미리 거른 `RouteView`** 만 준다. **이유**: 경로의 끝점이 곧 목적지다. 주문 칩 때는 매퍼(Codex 영역)에서 걸렀지만, 이번에는 아예 단계 데이터에 걸러진 값만 넣어 화면이 누설할 방법을 없앴다. 숨긴 구간은 차 앞 900 m 에서 끊기고 그 끝이 "안개"다. 테스트: 숨긴 뷰의 끝은 목적지에서 항상 300 m 이상.
- **결정**: 스킨은 런타임 전환 기능이 아니라 **d-road 의 색을 바꾸는 것**으로. **이유**: 미리보기는 전역 변수로 빨리 만들었지만 제품에 스킨 전환은 필요 없다.
- **결정**: `emu_flow.sh` 를 지도 작업 **전에** 고쳤다(공개 판정을 로그로, 시연 버튼 좌표 기억). **이유**: 지도가 움직이면 공개 화면도 `uiautomator dump` 가 안 된다 — 주행 화면에서 이미 겪은 문제. 안 고치면 Codex 가 "전체 여정 PASS"를 만들 수 없다.

### 막힌 것과 해결

- **경로 테스트 2개 실패**(길이 13878.8 vs 13889.3, 앞쪽 901.0 m > 900) → 로직이 아니라 단위 문제: 경로 길이는 대원 거리, 화면 좌표는 평면 투영(0.1% 차이). 허용치를 비율(0.5%)로.
- **PR 이 세 단으로 쌓임**(#14 ← #15 ← route) → 머지 승인 없이 후속을 계속 진행한 결과. squash 저장소라 단마다 `rebase --onto` 가 필요하다. 다음부터는 작업을 이어 가기 전에 머지를 먼저 요청한다.
