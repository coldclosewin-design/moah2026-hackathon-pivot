## 결정과 이유

- **결정**: 시연 주인공을 **일반 도로 주행 → 후면 직각 주차 과제**로. **이유**: 주차가 사용자 답변에 세 번 나왔고, 초보의 두려움이 가장 큰 곳이며, 채점 근거(조향 왕복·기어 전환·시간)가 선명하고, 시연 공간이 주차장 한 칸이다. 저속이라 **화면을 봐도 되는 유일한 주행 구간** — 도로에선 음성만, 주차에선 도식이 살아난다. **되돌릴 조건**: 사내에서 조향각·기어 신호가 둘 다 없고 Signal Simulator 로도 못 만들면 도로 주행(속도 중심)을 본편으로 되돌린다 — 설계는 둘 다 같은 상태기계라 비용이 작다.
- **결정**: 채점은 **과정만**(이동 구간·시간·급조작 + 조향 왕복·기어 전환·근접). 칸 안 위치는 모른다고 둔다. **대안**: Fake 로 최종 위치까지 판정하는 척. **이유**: 카메라가 없다. 발표에서 "어떻게 아느냐"에 답할 수 없는 기능은 넣지 않는다.
- **결정**: 모드는 **가이드(신호 확인형) → 힌트 → 평가 → 지식 테스트(3지선다)**, 앱이 실력 보고 자동 제안 + 운전자 오버라이드. **이유**: "아예 모르는 사람"도 쓰게 하려면 채점 없는 가이드가 먼저. STT 는 자리만 두고 사내 확인 후.
- **결정**: 멘트는 **프로필 기반 위트**("장롱의 문 정도는 열었습니다"), 시드 풀 + AI 변주, 같은 점수에 같은 말 반복 금지. 숙련 축과 안전 축 분리, 상대 위치는 같은 단계 사용자 기준·본인 화면에선 문장으로 순화. **이유**: 두려움을 줄이는 앱이 "하위 20%"라고 말하면 역효과.
- **결정**: 보상은 **구조 A(공유 범위 3단계·철회) + 수신자 예시 B(UBI)·C(인증)**. **이유**: 운전자가 주도권을 쥐어야 "감시하는 문서" 질문을 막고, UBI 는 한국에 실존해 현실 근거가 되며, 인증은 고령운전자 서사를 연다.
- **결정**: 프로필은 **자기 진술 5문항 + 관측**. 진술과 관측이 어긋나면 앱이 제안한다. **이유**: "앱이 실력을 보고 제안"의 근거가 필요하고, 위트 멘트의 재료가 된다.

## 막힌 것과 해결

- **증상** 첫 빌드에서 급조작 관련 테스트 5건이 한꺼번에 실패 → **원인** 두 개. ① `HarshEventDetector` 디바운스 초기값을 `Long.MIN_VALUE` 로 두고 `t - last >= debounce` 를 계산하자 **오버플로**로 음수가 되어 이벤트가 영영 안 잡혔다. ② 창 3 이동 평균이 0.15 s 간격 샘플의 진짜 급정지(-3.7 m/s²)를 -2.5 로 깎아 임계 아래로 보냈다 → **해결** ① nullable 로. ② 이동 평균을 버리고 **300 ms 고정 시간창 차분**(창보다 촘촘하면 창 너비로 묶고, 성기면 이웃 차분) → **교훈** 시계열 미분은 "샘플 수"가 아니라 "시간"으로 창을 잡는다. `Long.MIN_VALUE` 는 뺄셈에 쓰지 않는다.
- **증상** 가이드 모드 테스트 NPE — 회차 시작 직후 `guide` 뷰가 null → **원인** `SignalRegistry` 가 구독의 첫 emit 을 받기 전이라 모든 신호가 MISSING → `GuideRunner.start()` 가 6단계를 "확인 없이 읽고 넘김" 으로 한 번에 소진 → **해결** 회차 시작 때 `vehicle.get(KEYS)` 로 현재값을 먼저 레지스트리에 심음(`startAttempt` 가 suspend 로) → **교훈** "값이 안 오면 MISSING" 규칙은 **관찰 시간이 0 이면 전부 MISSING** 이 된다. 판정 전에 스냅샷을 한 번 읽는다. Real 의 `get` 동작은 가정(INTEGRATION B절).
- **증상** `GuideRunner` 가 벨트·시동·R 이 이미 다 돼 있는 스냅샷에서 한 단계만 넘어감 → **해결** 같은 스냅샷으로 연달아 확인(움직임 조건 단계는 새 스냅샷 대기) → **교훈** 운전자는 앱보다 빠를 수 있다.
- **증상** 상태기계 테스트에서만 급정지 힌트가 안 나옴(채점기 직접 테스트는 통과) → **원인** 테스트가 `(28.65-28.5)*1000` 을 `toLong` 으로 잘라 149 ms → 300 ms 창이 299 ms 로 빗나감 → **해결** 검출기에 20 ms 허용오차(`WINDOW_TOLERANCE_MILLIS`), 테스트는 반올림 → **교훈** 시간창 판정은 항상 지터 여유를 둔다. 에뮬 틱도 정확히 500 ms 가 아니다.
- **증상** 멘트 풀 "3회 반복 금지" 실패 → **원인** 태그 최적 후보가 2개뿐 → **해결** 신선한 후보가 없으면 같은 밴드 전체로 넓힘(반복 금지 > 태그 적합).
- **증상** 회차 시간이 26 s 가 아니라 22 s → **원인** `totalMillis` 가 마지막 **속도** 샘플까지만 → **해결** 마지막 delta 또는 "다 됐어요" 시각(`untilMillis`)까지.
- **증상** `speedRamp` 가 0.15 를 세 번 더해 28.8 을 28.799999… 로 만들어 스텝이 겹침 → **해결** 시각을 `from + i*step` 정수 배수로 → **교훈** 부동소수 누적 덧셈 금지. 테스트로 고정.
- **증상** 주차 시연이 도로 주행보다 미확인 신호(조향각·기어)에 더 의존한다는 것을 문서를 쓰며 발견 → **대응** A층(속도만)으로 회차 피드백이 성립하도록 지표를 다시 갈랐고, 배지 "실신호 N · 시뮬 N · 미측정 N"으로 숨기지 않기로. 사용자에게 알렸고 수용. **교훈** 주인공을 바꾸면 신호 의존 지도를 다시 그린다.
