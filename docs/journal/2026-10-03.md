## 결정과 이유

- **결정**: 전면 주차를 위한 코드 변화를 **사양 하나(`ParkingSpec`)로 한정**하고, 점수·판정 규칙은 손대지 않는다. **대안**: 과제별 채점기/판정기 분리. **이유**: 후면과 다른 것은 진입 기어·목표 각·키뿐임을 코드에서 확인(판정은 `abs` 로 부호 무관, 궤적 추정은 기어로 방향을 안다). 고정값 테스트·`emu_flow` 가 안 깨졌다. **되돌릴 조건**: 평행·사선처럼 목표 각이나 구간 구조가 다른 과제를 붙일 때 사양만으로 부족하면 그때 확장.
- **결정**: 전면 주차는 뒤 거리(Fake 전용)를 **아예 쓰지 않고** 배지 분모 7. **대안**: 앞 거리 Fake 신호를 새로 만들기. **이유**: 실물에 없는 경로를 하나 더 만드는 셈이고, 근접은 실물 `IsWarning` 하나로 충분(사내 실측 7/1/0 의 시뮬 1 이 바로 뒤 거리). 화면은 그 칸을 "미측정" 이 아니라 **빼야** 한다 — 안 재는 것과 못 잰 것을 구분(발주 2.2). **되돌릴 조건**: 사내 Signal Simulator 에 앞 거리 값이 있으면.
- **결정**: 질감 B 는 **토큰 한 곳 + 대상 다섯**(주 버튼·칩·과제 카드·판정 패널·점검 패널)로 한정, 도식·글자·잠금 화면은 평면 유지. **이유**: 브리프의 "입체 그림자 싫음(종이 UI)" 은 과한 입체에 대한 것이었고 사용자가 "살짝" 을 원함 — 수치 상한(알파 10~28 %, blur ≤ 28 dp)을 D7 로 적어 되돌릴 수 있게. **되돌릴 조건**: 사내 디스플레이에서 글자 대비가 떨어지면(확인 항목 ⑦).
- **결정**: 동결은 10/6 그대로, 그래서 ③(퀴즈 확장·서두 정리)은 선택. **이유**: 사용자 결정. 라운드 13 ①②가 10/4~5 리뷰까지 끝나야 재녹화·덱 캡처가 10/6 에 맞는다.

## 막힌 것과 해결

- **증상** 전면 흐름 스크립트가 600 s 를 넘겨 백그라운드로 → **원인** 에뮬이 죽어 있었다(`no devices`, 10/2 와 같은 플레이크) — `adb logcat -d` 대기 루프가 90 s 씩 돌았다 → **해결** 콜드 부팅(`-no-snapshot-load`) + `sys.boot_completed`·load < 2 대기 뒤 재실행 → **교훈** 에뮬 스크립트는 첫 줄에서 `adb get-state` 로 기기를 확인하고 없으면 즉시 종료(`inhouse_check.sh` 는 그렇게 돼 있다, 내 임시 스크립트는 아니었다).
- **증상** `ParkingRecorderScenarioTest` 전면 good 배지가 `simulated=6 missing=1` → **원인** 레코더 단독 테스트는 회차 시작의 `get()` 이 없어 시나리오가 안 건드린 도어 키가 미측정 → **해결** 테스트는 분모 7 만 고정하고, 7 시뮬은 상태기계 테스트가 고정 → **교훈** 배지 숫자는 "누가 키를 처음 봤나" 에 달려 있다 — 레코더 테스트와 앱 동작을 같은 숫자로 기대하지 않는다.
- **증상** 거부 문장 테스트 실패 → **원인** READY 과제 목록에 전면이 들어가 "지금은 … 할 수 있어요" 문장이 바뀜 → **해결** 기대 문자열 갱신. 의도한 변화.
- **증상** 큰 python heredoc 이 Bash 파싱 실패(10/2 밤, 제출물 원고 편집) → **해결** 스크립트를 파일로 쓰고 실행(CLAUDE.md 셸 함정 그대로) → **교훈** 한국어 치환이 10개를 넘으면 처음부터 파일로.
