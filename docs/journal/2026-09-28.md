## 결정과 이유

- **결정**: 라운드 3 에서 고정했던 바퀴를 **다시 돌린다** — 단, 애니메이션으로. **이유**: 고정한 이유가 "툭 바뀌는 게 어색하다" 였고 사용자가 이번엔 "자연스러운 애니메이션으로 바퀴 전환" 을 요청했다. 정지 그림(시안 B)은 그대로, 움직임만 붙는다. 결정을 뒤집는 게 아니라 원인을 없애는 것.
- **결정**: 조향각 숫자(`450°`)는 남기고 풀이 문구를 **더한다**. **이유**: 기어·뒤 거리 cm 와 같은 계기 값이라 "운전자 문장 숫자 없음" 규칙의 대상이 아니다. 풀이는 문장이라 숫자 없이(`한 바퀴 반`).
- **결정**: 시간 감점 유예 45 → 60 s. **이유**: 위 "막힌 것". 채점표는 "값으로 노출돼 조정 가능" 이라고 덱에도 적어 둔 항목이고, 시나리오 고정값은 변하지 않는다.
- **결정(사용자 9/28)**: `시연` 토글 = 알약(무텍스트), `조수석` 눈썹 = `코치`. 드래프트 PR 캡처 두 장으로 골랐다.
- **결정**: Done 궤적은 **데이터가 아니라 그리기**를 바꾼다 — 캔버스 180° 회전으로 Maneuver 의 "뒤가 위" 에 맞춘다. **이유**: `PathReconstructor` 좌표계(+y = 앞) 위에 채점·테스트가 있고 물리가 맞다. 잘못 읽히는 건 관습 불일치이므로 관습을 통일하는 게 답이다. 셰브론은 Maneuver 와 같은 언어라 새 요소가 아니다.
- **결정**: 급제동 임계 -3.5 → -3.0, 시나리오 4.0 → 4.8 km/h. **이유**: "막힌 것" — 임계는 제품 기준(UBI 3 m/s²)으로 정하고 시나리오는 그 위를 넉넉히 넘게. 두 값 다 채점 고정값을 바꾸지 않는다.
- **결정(사용자 9/28)**: 과제 시트는 **시안 05(큰 글자 메뉴 + 주차 칸 도식)**. 초기 4안(A~D)이 아니라 A 를 바탕으로 한 후속 5안 중 조합안. **이유(사용자)**: A 의 접근성·가로 2단은 좋되 선택 대비·계층 구분·세부 4개·확연히 다른 블록을 원했다.

- **결정(사용자 9/28)**: **동승자 공유 제거** — 만든 지 하루 만에 "운전자 입장에서 불필요". **이유(사용자)**: 운전석 화면에 동승자용 콘텐츠가 있을 이유가 없다. **내 판단**: 화면만 빼고 모델을 남기면 죽은 코드라 전부 뺀다(git 이력 PR #40~#43). 교훈은 "배운 것" 에.

- **증상** 도구 변경 확인용 `emu_flow` 가 두 번 연속 FAIL — 회차 1 숙련 58(기대 60). 1회차: 급제동 힌트가 안 나와(안전 70) 그 대기 타임아웃 10 s 가 회차에 들어감. 2회차: 힌트 3종·안전 55 정상인데 회차가 t+57 s 로 끝나 55 s 경계 초과. → **원인** 어제 "여유 2 s" 라고 적은 경계가 뒤집힌 것. 못한 주차 44 s + 도구 지연 10~13 s 가 유예 45 s + 10 s 블록 경계(55 s)에 걸쳐 있다. 스크립트 변경(`(text|content-desc)` grep)은 탭 재시도 0 으로 무관. → **해결** `ParkingRubric.graceSeconds` 45 → **60**(경계 70 s). 초보의 후면 주차 1 분은 감점 대상이 아니라는 제품 판단과도 맞다. `ParkingScorerTest` 의 시간 감점 테스트는 유예 기준 상대값으로. 시나리오 고정값(60/55·100/100)은 그대로(44 s < 45 였으니 원래 시간 감점이 없던 값). → **교훈** 어제 일지에 "다음에 또 넘으면 `graceSeconds` 를 의심한다" 고 적어 둔 덕에 바로 갔다. 도구 지연이 채점에 들어가는 구조에서 경계 여유 2 s 는 여유가 아니다.
- **증상** 급제동 힌트가 안 나오고 안전 70 — 아침 확인 실행 1회, 라운드 5 재녹화(녹화 부하) 1회, **두 번**. → **원인** 못한 주차의 급정지는 4 km/h → 0 을 0.3 s(-3.7 m/s²)인데 임계가 -3.5 라 **여유가 17 ms**. 검출기는 300 ms 창의 양 끝 샘플 차분이라 마지막 정지 샘플이 17 ms 만 늦어도 가속도가 -3.5 를 못 넘는다. 샘플 시각은 배달 시각(정직)이라 에뮬 부하가 그대로 들어간다. → **해결** 임계 -3.5 → **-3.0**(가속 +3.0 과 대칭, 문서의 "3 m/s² 근처") + 시나리오 3구간 속도 4.0 → **4.8 km/h**(잠금 5 미만) → -4.4 m/s², 여유 **144 ms**. `ParkingRecorderScenarioTest` 에 "마지막 샘플 120 ms 지연에도 급제동 1건" 테스트. 채점 고정값(60/55) 불변. → **교훈** 시연 시나리오의 "정확히 임계값" 설계는 부하에 깨진다 — 유예 45 s 와 같은 종류. 임계는 시나리오가 아니라 제품 기준으로 정하고, 시나리오는 그 위를 넉넉히 넘게 만든다.

## 배운 것

- 피드백이 "움직임" 으로 옮겨 왔다는 건 배치·문장이 자리를 잡았다는 뜻이다 — 라운드마다 피드백의 층이 내려간다(구조 → 문장 → 모션).
- 사용자 결정이 필요한 항목은 **캡처 두 장**으로 묻는 게 가장 빠르다 — 말로 설명한 안은 고르기 어렵다(9/26 톤 확정 때도 같았다).
- 정지 그림으로 승인된 시안도 **움직이면** 다르게 읽힌다 — 시안(시작 차 위, 끝 차 아래)은 맞았지만 재생을 붙이자 "나가는 차" 가 됐다. 움직이는 아이콘은 코 방향으로 간다고 읽히고, 화면 사이의 관습(뒤가 위)은 하나여야 한다.
- 시연 시나리오를 "정확히 임계값" 으로 설계하면 부하에 깨진다 — 유예 45 s(여유 2 s)와 급제동 -3.7(여유 17 ms) 둘 다 같은 날 뒤집혔다. 임계는 제품 기준, 시나리오는 그 위를 넉넉히.
- 하루에 라운드 셋을 돌릴 수 있었던 건 **불변 표 + 원본 스크립트 PASS** 가 완료 기준이라서다. 리뷰가 "돌려 보고 눈으로 본다" 로 끝나고, Codex 는 발주서 §2 를 계측으로 그대로 옮긴다. 사용자 승인 예외로 도구를 고칠 땐 원인 분석이 같이 온다.
- 사용자가 Codex 세션에서 직접 고른 결과(시안 README 첫 줄)는 **이 대화에서 한 번 더 확정**받고 움직인다 — 문서에 적힌 "선택" 은 데이터지 승인이 아니다.
- **"후순위 목록에서 고른 기능" 은 만들기 전에 사용자에게 한 문장으로 되물어야 한다.** 동승자 공유는 사용자가 "발주서 써 줘" 라고 했지만, 그 전 대화는 "미룬 것이 뭐가 있나" 였다 — 확인이 아니라 탐색이었다. 발주서 단계에서 "이걸 정말 넣을까요?" 를 물었으면 PR 4개(#40~#43)와 재녹화 한 편이 없었다. 다음부터 새 기능 발주서 첫 줄에 "왜 지금" 을 쓰고 확인받는다.

- **결정**: 배지 분모를 과제별 키 집합으로 자른다(레지스트리는 상위 집합). **이유**: 점검 신호 4개를 레지스트리에 넣으면 주차 배지가 "미측정 4" 가 된다 — 시연 본편 불변.
- **결정**: `ReservationCard` 를 내 PR 에서 지우지 않고 Codex 화면 PR 에서 함께 지우게 했다. **이유**: 소유 경계 — 상대 영역을 깨는 변경은 발주서 메모로 넘긴다.
- **결정(사용자 9/28)**: Done 궤적 = (나) 도착 칸. **내 권장 이유**: 덱 마지막 줄 "칸에 반듯이 들어갔는지는 모릅니다" 와 화면이 같은 말을 해야 한다. 시간을 뒤집으면 후진 구간·급정지 점이 거짓이 된다.
- **결정**: 열린 PR 셋의 머지 순서를 제안하고 사용자가 "제안대로" 라고 하면 리뷰·머지·리베이스까지 한 번에 진행한다. **이유**: 머지 승인은 사용자 몫이지만, 순서가 정해진 뒤의 리베이스·재검증은 리뷰어 일이다.
