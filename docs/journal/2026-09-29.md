## 결정과 이유

- **결정**: #55 는 화면이 아니라 **계측 대기 방식**을 고치게 했다. **대안**: 리뷰 환경에서만 흔들리니 그냥 머지. **이유**: 완료 기준이 "원본 `lesson_shots` PASS" 인데 리뷰 환경에서 0/3 이면 기준이 무의미해진다. 전환 애니메이션이 들어온 라운드라 앞으로도 같은 종류의 흔들림이 생긴다 — 고정 대기 대신 정착 폴링을 계약의 기본 도구로 만든다. **되돌릴 조건**: 없음.
- **결정**: 녹화 시간 한도를 없앤다(`--time-limit 0`). **이유**: SIGINT 로 멈추므로 한도가 할 일이 없고, 세션 길이가 부하에 따라 135~150 s 로 흔들려 180 s 가 남지 않는다.
- **결정**: 이관 번들에 **브랜치 + 태그**를 담고, 태그를 origin 에도 push. **이유**: 런북 0절 항목이고, 사내에서 뭘 가져갔는지 나중에 알 수 있어야 한다. 번들은 clone 테스트를 통과한 것만 준다.

## 막힌 것과 해결

- **증상** `emu_flow` 가 회차 1 `asked done` t+385 s, 채점 로그 없음, adb "Broken pipe". → **원인** 에뮬 2.5 일 가동 끝에 시스템 서버 과부하(load 24). → **해결** `adb reboot` → 부팅 뒤에도 4 분간 load 20+ (gms·인덱싱) → 4 미만까지 폴링 대기 → 정상. → **교훈** 리뷰 전 `adb shell uptime` 한 줄. 오래 켠 에뮬은 재부팅하고 **부하가 내려갈 때까지 기다린 뒤** 돌린다(어제 TTS 프로세스 잔류와 같은 계열).
