## 결정과 이유

- **결정**: 사내 전환을 "compileOnly 한 줄 교체" 에서 **"추적 안 되는 설정 한 줄 + jar"** 로. **대안**: 사내 전용 브랜치 `inhouse/real-vss` 유지. **이유**: 사내에서 코드를 고치면 사외로 돌아오지 못해 갈라진다(9/30 1차 이관에서 실제로 벌어짐). 같은 커밋이 양쪽에서 빌드되면 전달 단위가 태그 하나로 줄어든다. **되돌릴 조건**: 사내 jar 가 compileOnly 로 해결되지 않는 API 차이를 드러낼 때 (PR #62, `docs/07`).
- **결정**: AI 코치는 **Cloud Copilot 하나**, 로그인은 device code, 실패는 전부 규칙 문장 폴백. **대안**: 온디바이스 보드 대기. **이유**: 사내 1차에서 온디바이스 보드가 제공되지 않았고, 시연은 Fake 로 완결되어야 한다는 원칙이 그대로다. 로그인은 사람이 GitHub 에서 Authorize 까지 눌러야 하므로 패널에 코드·주소를 큰 글자로 보인다 (PR #64·#66).
- **결정**: #61 리뷰에서 `과` 중복은 **머지를 막지 않고** 라운드 10 후보로. **이유**: 발주서 "세 항목까지 모두" 를 충족하고, 사내 관찰 노트가 오면 어차피 한 묶음 발주가 생긴다.

## 막힌 것과 해결

- **증상** `gradlew assembleDebug` 가 1 초 만에 "Task 'assembleDebug' not found in root project 'hybrid'" — `settings.gradle.kts` 는 main 과 동일하고 `--info` 로는 평가되는데 `include(":automotive")`·`rootProject.name` 이 반영되지 않음. 워크트리 `.gradle/`·`.kotlin/` 삭제·데몬 재시작 무효. → **원인** `~/.gradle/caches/8.10.2/kotlin-dsl/scripts/` 의 **컴파일된 settings 스크립트 캐시 엔트리 손상**(같은 날 03:33 캐시 GC 흔적). 파일에 줄 하나를 넣어 내용 해시를 바꾸면 정상, 되돌리면 재발 — 그래서 Codex 는 CRLF → LF 정규화로 "고쳐진" 것으로 봤다(해시가 바뀌었을 뿐). → **해결** 사용자 승인 뒤 그 폴더 삭제(자동 재생성). → **교훈** 프로젝트 안을 다 지워도 안 되면 사용자 캐시의 컴파일 산출물을 의심한다. `.gitattributes` 는 손대지 않는다 (`docs/03_environment.md` 함정, PR #66 코멘트).
