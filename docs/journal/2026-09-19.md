## 결정과 이유

- **결정**: 실내 안내를 넣는다. 단 건물 1곳·도착 화면에만·약도. **대안**: 나중에 / 여러 건물. **이유**: 지금 선물은 "현대백화점"이 아니라 "5층 식당가 끝 창가 자리"인데 앱은 주차장에서 끝난다 — 마지막 100 m 가 빈다. 넣으면 주행 지도 → 공개 → 주차 접근로 → 도착 → 자리까지가 한 이야기가 된다. **되돌릴 조건**: Codex 작업이 하루를 넘기면 단계 목록(글)만 남기고 분해도는 뺀다.
- **결정**: 경로를 미리 짜 두지 않고 **계산한다**. **이유**: 사용자가 말한 것은 "빠른 경로"다. 시드 그래프라도 실제 계산이면 "7개 층은 엘리베이터, 1개 층은 에스컬레이터"가 테스트로 증명되고, 발표에서 연출이 아니라 기능이라고 말할 수 있다.
- **결정**: 도착 화면에만 보인다(공개 화면 아님). **이유**: "5층 식당가"는 선물 내용이다. 공개 화면은 쿠폰·메모·예약을 보여 주지 않는다는 규칙이 있고 계약 테스트가 지킨다.
- **결정**: 화면에 "약도예요. 실제 매장 배치와 다를 수 있어요."를 고지한다. **이유**: 실존 건물의 내부를 시드로 그린다. 틀린 도면을 사실처럼 보이게 하지 않는다.

## 막힌 것과 해결

- **엘리베이터 시간이 104초로 나옴**(테스트를 쓰다 발견) → 대기 40초를 "로비 ↔ 승강로" 연결에 넣었는데 연결이 양방향이라 내릴 때도 40초가 들었다 → 타기·내리기 각 20초로(합 40초). **교훈**: 기대값을 손으로 먼저 계산해 두면 모델의 오류가 테스트를 쓰는 순간 드러난다.
- **핸드오프 문서에 첫 단계 라벨을 틀리게 적음**("주차 구역 E3 …" → 실제는 "E3 엘리베이터 앞까지 걸어서") → 라벨 생성 규칙을 다시 읽고 정정. 핸드오프에 적는 예시는 코드가 실제로 내는 값이어야 한다.
- **문서 갱신·커밋·PR 을 셸 스크립트 하나에 몰아넣었다가 따옴표 파싱 오류로 통째로 실행 안 됨** → 아무것도 실행되지 않았음을 `git status` 로 확인한 뒤 파일 도구로 나눠서 진행. 큰 heredoc 안에 작은따옴표가 든 한국어 문서를 넣지 않는다(9/18 에도 같은 오류가 한 번 있었다).

### 결정과 이유

- **결정**: 공개·도착 화면에도 자막을 넣는다. **이유**: 제출물은 영상이고 음성 품질은 미결이다. 소리 없이 보면 지인의 메모를 읽는 순간과 "E3 엘리베이터가 제일 빨라요" 가 화면에 남지 않는다 — 시연의 절정에 글자가 없다. 주행 화면의 "자막은 항상 보인다" 규칙을 공개·도착으로 넓힌 것.
- **결정**: 계약은 시그니처를 바꾸지 않고 **오버로드를 추가**. **이유**: 시그니처를 바꾸면 Codex 의 d-road 구현과 계약 테스트가 같이 깨져 내 PR 에서 남의 영역을 고쳐야 한다. 기본 구현이 기존 화면에 위임하면 main 은 그대로 돌고 Codex 가 자기 PR 에서 구현만 얹는다.
- **결정**: 공개 구간의 빈 자리에는 남은 **거리**만, 시간은 넣지 않는다. 숨긴 구간에는 거리도 넣지 않는다. **이유**: 시연은 거리를 10배 압축하므로 시간은 거짓말이 되고, 숨긴 구간의 거리는 목적지를 좁히는 단서다.

### 막힌 것과 해결

- **녹화 중 `screencap` 으로 찍은 검토용 스크린샷이 하나도 저장되지 않음**(스크립트는 "shot" 이라고 찍었다 — 성공 여부를 확인하지 않는 echo 였다) → 영상에서 같은 시각의 프레임을 ffmpeg 로 추출. 영상이 원본이므로 오히려 낫다. **교훈**: 로그의 "했다" 는 했다는 증거가 아니다. 산출물 파일을 세어라.


### 4차 세션(이어서) — PR #27 리뷰·머지, 문장 단위 자막

- PR: [#26](https://github.com/coldclosewin-design/moah2026-hackathon/pull/26) squash `ae6d3cb`, [#27](https://github.com/coldclosewin-design/moah2026-hackathon/pull/27) squash `fb69f99` → `claude/sentence-subtitles`
- **(리뷰)** PR #27: 직접 빌드, 단위 58, 계약 PASS, 계측 10 + 15, 전체 여정 PASS(117초). 시연을 다시 녹화해 5건 반영 확인(자막, 칩·이름표 자리, 남은 거리, 물음표 추적, 정차 상태의 길). 수정 요청 없이 머지.
- **(ports)** `splitForSpeech`: 한 번의 `speak()` 를 자막 한 장 크기(48자)의 문장 토막으로 나눠 큐에 넣는다. 자막은 지금 말하는 토막. URGENT 는 첫 토막만 끊고 말하기, 스토리 드롭 기준은 토막이 아니라 발화 수. 재녹화로 최종 도착 자막이 한 줄씩 넘어가고 카드·도장 줄이 원래 자리인 것 확인.

#### 결정과 이유

- **결정**: 도착 멘트를 상태기계에서 쪼개지 않고 **TTS 포트 안에서** 나눈다. **이유**: 호출부와 테스트(`tts.spoken`)는 "무엇을 말하는가"를 보고, 나누기는 "어떻게 말하는가"다. 포트 안에 두면 상태기계·Fake·기존 테스트가 그대로다. 엔진이 없는 환경은 언제 넘길지 알 수 없으므로 전문을 한 번에 보여 준다(Codex 의 네 줄 배치가 그 경우를 받는다).
- **결정**: PR #27 을 "두 줄 조건 위반"으로 돌려보내지 않았다. **이유**: 12문장이 두 줄에 안 들어가는 원인은 화면이 아니라 내 쪽(한 발화)이었다. Codex 는 배치를 자막 높이에 맞춰 동적으로 만들었으므로 원인을 고치면 화면은 저절로 돌아온다 — 실제로 그랬다.

#### 막힌 것과 해결

- **스크립트로 Kotlin 정규식을 써 넣다가 역슬래시가 한 겹 벗겨져 들어감** → 결과 줄을 grep 으로 확인해 발견, 파일 도구로 수정. 이스케이프가 두 겹인 내용은 셸 heredoc 안의 스크립트로 쓰지 않는다.
- **내 테스트의 기대값이 틀림**(마지막 토막이 "민지의 마지막 메시지예요…" 로 시작할 것이라 가정, 실제는 48자 제한으로 한 문장이 다음 토막으로 넘어감) → 기대값을 규칙에서 다시 계산해 수정.
- **PR #26 에서 이 일지의 "배운 것" 제목을 지웠다**(치환 스크립트의 대체 문자열에 제목을 다시 넣지 않았다) → 이번에 제목 목록을 뽑아 보다 발견, 복구. 문서를 스크립트로 고친 뒤에는 제목 목록(`grep "^## "`)을 확인한다.
