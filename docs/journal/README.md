# 개발일지 (docs/journal)

매일 한 편. 나중에 **기술 블로그 연재**와 **해커톤 발표 자료**의 원재료가 된다. 그래서 "무엇을 했다"보다 **"왜 그렇게 결정했고, 어디서 막혔고, 무엇을 배웠나"**를 남긴다.

## 규칙

- 파일명 `YYYY-MM-DD.md`. 하루에 여러 세션이어도 한 파일에 누적.
- 작성자: Claude Code가 세션 끝에 초안을 쓰고, 사용자가 자기 생각(감상·판단 근거)을 `> 💬` 인용으로 덧붙인다. 발표에서 가장 힘 있는 문장은 사용자의 것이다.
- Codex의 작업은 PR 본문에서 가져온다. Codex는 일지를 직접 쓰지 않는다.
- 모든 항목은 **근거 링크**(커밋 해시, PR 번호, 문서 경로, 스크린샷)를 단다. 블로그로 옮길 때 그대로 인용한다.
- 숫자(테스트 수, 소요 시간, 라인 수)는 표에만. 문장에는 넣지 않는다.
- 스크린샷은 `docs/screenshots/`에 두고 일지에서 상대 경로로 참조.

## 섹션 (템플릿 `_template.md`)

| 섹션 | 목적 | 블로그/발표 용도 |
|---|---|---|
| 한 줄 요약 | 그날을 한 문장으로 | 연재 목차, 발표 타임라인 |
| 오늘의 목표 → 결과 | 계획 대비 실제 | 진행률 그래프 |
| 한 일 | 커밋·PR 단위 사실 | 기술 상세 |
| 결정과 이유 | 갈림길에서 무엇을 왜 골랐나 | **발표의 핵심 슬라이드** ("왜 이렇게 만들었나") |
| 막힌 것과 해결 | 삽질 기록 | **블로그에서 가장 읽히는 부분** |
| 배운 것 | 한 줄짜리 인사이트 | 회고 슬라이드 |
| 지표 | 테스트 수, 빌드 시간, 커버한 흐름 | 정량 슬라이드 |
| 에이전트 협업 메모 | Claude/Codex 분담이 어떻게 굴러갔나 | "1인 팀 + AI 에이전트 2개" 스토리 |
| 내일 | 다음 할 일 | 다음 편 예고 |
| 발표 소재 | 인용할 문장, 쓸 스크린샷, 데모 순서 | 발표 스크립트 재료 |
