## 결정과 이유

- **결정(사용자)**: 픽업 메모는 A안 + 힌트 2. **이유**: 내용("엄마랑 데이트할 때")이 기분 '데이트'와 맞물려 지금 메모보다 좋지만, 4문장은 72sp 에서 4~5줄·음성 8초라 차 안에서 길다.
- **내 제안의 철회**: 마지막 메시지를 "맨 끝에 나타나게"(9/20 B안의 4번)는 내 제안이었는데, 사용자가 영상을 보고 "갑자기 뜬금없이 나온다"고 지적했다. 맞다 — 29초 동안 없던 글이 생기는 것은 엔딩이 아니라 돌발이다. 처음부터 보이고 읽을 때 강조만 옮기는 쪽으로 다시 제안(결정 대기). **배운 것**: "마지막 변화가 엔딩이 된다"는 것은 글로는 그럴듯했지만 영상으로는 아니었다. 연출은 말로 검토하지 말고 찍어서 본다.
- **결정(사용자)**: 마지막 메시지·가독성 두 건 모두 적용. 가독성의 범위는 사용자가 정하지 않아 **전체 화면을 한 오더에, 우선순위를 매겨**(최종 도착 → 도착 공통 → 공개 → 주행 → 기분) 넣었다. **이유**: 3주차라 오더를 여러 번 도는 비용이 더 크다. 대신 1부(마지막 메시지)는 작고 급하므로 PR 을 나누게 했다.
- **결정**: 글자를 키우는 방법으로 "밀도 배율을 올려 전부 같은 비율로 키우기"를 택하지 않았다. **이유**: 어제의 실험이 바로 그것이었고(1.25배) 화면이 넘쳤다. 글자가 커지면 담기는 내용이 줄어드는 것은 피할 수 없으므로, 배치와 문구 양을 같이 고치는 것이 맞다. `DesignScale` 은 "어느 기기에서나 같은 모습"만 책임진다.
- **결정(사용자)**: 둘째 선물은 호칭 통일이 아니라 **다른 사람(친구 지훈)**으로. 9/20 에 나는 "한 아버지가 두 코스를 남긴 이야기"로 호칭만 맞추자고 했지만, 사용자는 여러 지인이 선물한다는 서비스의 성격을 택했다.
- **결정**: 통과 층 간격을 넓히며 내가 오더에 적었던 기준 두 개(머무는 층 판 두께 ≥ 28%, 걷는 토막 세로 범위 ≥ 6%)를 26%·5.5% 로 낮췄다. **이유**: 두 기준은 패널이 365dp 일 때 정한 것이고(102px·22px), PR #37 뒤 패널은 444dp 다 — 낮춘 비율로도 115px·24px 로 절대 크기는 더 크다. Codex 가 6.05% 로 기준에 딱 맞춰 둔 탓에 간격을 조금만 넓혀도 걸렸다. **배운 것**: 비율로 적은 기준은 분모가 바뀌면 의미가 바뀐다. 기준에는 절대 크기(dp)도 같이 적는다.
- **결정(사용자)**: 화랑공원 선물은 설렘에, 엄마가, 한 곳으로. '여유'를 AI 추천으로 비우자는 내 제안을 채택 — 여섯 기분 전부에 선물이 있으면 "선물이 없으면 AI 가 고른다"를 화면에서 보여 줄 수 없다.
- **결정**: 문구 확인을 기다리지 않고 초안대로 넣었다. **이유**: 구조(POI·경로·주차·테스트)는 문구와 무관하고 문구는 시드 한 곳이라 나중에 바꾸기 쉽다. 대신 지어낸 부분(벤치·주차장 위치)을 PR·NEXT·INTEGRATION 에 "확인하지 않고 지은 것"으로 적었다.
- **결정**: PR #33 에서 큰 "가는 길"이 정중앙이 아니라 메모 오른쪽 두 열에 뜨는 것(오더와 다름)을 수용. **이유**: 메모를 가리지 않고 이동 거리가 짧다. 사용자에게 다른 점을 알렸다.
- **결정(사용자)**: 음성은 네트워크 kob. **결정(Claude)**: 시간표는 온라인 실측에 맞춘다. **이유**: 시연·영상은 온라인이고, 오프라인에서는 화면이 음성보다 1~3초 늦게 따라가는데 앞서가는 것보다 낫다. 시간표 값은 `ui/` 와 테스트·계측의 시각 리터럴 10여 곳에 걸쳐 있어 `[cross]` 가 아니라 오더로 넘겼다.
