## 결정과 이유

- **결정**: 피드백을 "바로 고칠 것(라운드 20)" 과 "시안 먼저(라운드 21)" 로 나눠 Codex 를 놀리지 않는다. **이유**: 시안을 만드는 동안 Codex 가 단순 항목을 끝내 시간이 겹친다. 라운드 21 이 같은 화면을 다시 만지므로 라운드 20 은 구조를 바꾸지 않게 했다.
- **결정**: 시안 33안은 서브 에이전트 넷에 두 주제씩. **이유**: 정적 HTML 이라 서로 겹치지 않고 병렬이 쉽다. 공통 브리프(토큰·질감·형식)로 일관성을 맞췄다.
- **결정**: 지도 차 ×1.3 은 화면 상수 + 칸 데이터 ×1.3(후진 경로 끝도 칸 깊이만큼). **이유**: 차만 키우면 5.85 m 차가 5.5 m 칸을 넘는다.
- **결정**: lesson_shots 플레이크(매번 다른 타이밍 검사)는 머지를 막지 않고 라운드 21 ⑨ 로 굳힌다. **이유**: 실패 지점이 매번 다르고 앱 흐름(emu_flow·course_flow)은 PASS.

- **결정**: 프로필은 기존 `ProfileStatement` 필드 타입을 바꾸지 않고 칩 층(대표값 ↔ 칩)을 얹는다. **이유**: 멘트 태그·Copilot 프롬프트·과제 제안·화면 눈썹이 이미 그 필드를 읽는다 — 타입을 바꾸면 마감 나흘 전에 다섯 곳을 같이 고쳐야 한다.
- **결정**: 모델 PR 은 한 번에 하나(M1 → M2 → M3 → M4), 도구는 별도 tools PR. **이유**: "머지 승인 없이 쌓지 않는다" · "PR 하나 = 한 scope". 대신 각 PR 을 작게 해 승인 왕복을 짧게 했다.
- **결정**: 예약 카드 `모의시험` = 예약 코스 과제를 평가 모드로(발주서 초안의 "장내기능 과제" 가 아니라 4b 시안대로). **이유**: 시안 문구 "시험장 코스 그대로, 제가 채점만 할게요." 와 맞고, 주차 3종 예약에서도 뜻이 통한다.
