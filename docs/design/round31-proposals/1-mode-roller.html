손가락이 500 ms 동안 30 dp×3 올림(낱말이 1:1 따라옴) → 놓음 → 350 ms 스프링으로 56 dp×3 지점에 안착(살짝 넘쳤다 돌아옴). 임계 1/3 미만이면 제자리로 스프링.
장점
  • 손에 붙어 움직이니 "롤러" 감각이 가장 직접적이다 — 사용자의 "롤링형" 요구에 촉감으로 답한다.
  • 반대 방향(아래로)으로 이전 모드 — 세 모드 사이를 어느 쪽으로든 한 번에 간다.
  • 창·카드·겹침 없음.
주의
  • 공수 중간: `draggable` + `Animatable` + 임계 판정 + 탭 폴백. 드래그 중 다음 낱말의 위치 계산이 붙는다.
  • 차 화면은 미세 드래그가 서툴다(팔 거리·진동) — 탭 폴백이 필수라 결국 E 와 같은 탭 동작을 하나 더 가진다.

E세 점 + 위로 굴러감

누름 → 지금 낱말 위로 56 dp×3 나가고 다음 낱말 아래서 들어옴(한 띠로 묶여 같이 움직임, 스프링 360 ms) → 노란 점 옆 칸으로(280 ms). 점은 표시일 뿐 누르는 대상은 낱말 전체(높이 132 dp).
장점
  • "지금 셋 중 몇 번째" 가 늘 보인다 — 다른 모드를 미리 보여 주지 않아도 세 개뿐임을 알 수 있다.
  • 과제 ▼ 와 완전히 다른 기호(점 셋)라 "시트" 와 "굴러감" 이 섞이지 않는다.
  • 홈의 노란 포인트 자리가 생긴다(지금 홈엔 노란색이 없다). 겹침·카드·그림자 0.
  • 공수 작음: `AnimatedContent`(Vertically) + 점 Row 의 `animateDpAsState`.
주의
  • 점 셋이 6 dp×3 = 18 dp 로 작다 — 표시용이라 괜찮지만 운전석에서 "어느 점" 은 노란색으로만 구분된다(색약: 노란 점은 크기도 8 dp 로 더 크다).
  • 점의 위치가 어떤 모드인지는 순서(가이드→힌트→평가)로만 알 수 있다 — 설명 줄이 보완.
  • 밑줄과 점 사이 4 dp×3 — 설명 줄을 6 dp×3 아래로 내린다(모든 안 공통 262 → 266).

추천 · E 세 점 + 위로 굴러감 — 대안 A 세로 드럼

이유 한 줄: 카드·그림자 없이 낱말이 제자리에서 굴러가면서도 "셋 중 어디" 가 늘 보이고(점 셋 = 과제 ▼ 와 다른 기호), Compose `AnimatedContent` 한 줄 + 점 하나로 반나절 안에 끝난다.

  • A 를 고르는 경우: "세 모드가 한꺼번에 보이며 돈다" 는 롤링 그 자체를 원하면. 공수 중간(창 열림 상태 + 마스크 + 윗줄 흐림).
  • C 는 가장 적은 코드지만 다른 모드가 미리 안 보이고, B 는 "슬라이드" 로 읽혀 롤링 요구에서 멀고, D 는 차 안 미세 드래그가 서툴어 결국 탭 폴백(= E)을 갖는다.
  • E 에 D 의 위아래 스와이프를 선택으로 붙일 수 있다(`draggable` 로 임계 넘기면 탭과 같은 전환) — 1 차엔 빼고 탭만.
공수 작음 · 반나절 미만

모든 안 공통 구현 메모

  • 슬롯 폭 = `가이드` 측정 폭 고정(`Modifier.width(IntrinsicSize)` 대신 세 낱말 중 최대 `measureText`) → 뒤 문장이 밀리지 않는다. 밑줄은 슬롯 폭 전체.
  • 아래 설명 줄("틀린 순간에만 말할게요." ↔ "단계마다 제가 말하고 확인해요." ↔ "조용히 지켜보고 끝에 판정해요.")은 낱말이 멈춘 뒤 `Crossfade(200 ms)`.
  • 과제 쪽 `▼` 는 그대로(시트) — 모드 쪽만 새 기호. 접근성 이름 `과제·모드 바꾸기` 유지, `stateDescription = "지금 힌트"`.
  • 기존 모드 팝업(두 겹 카드)·`ModeWheel` 은 지운다. 예약 카드 위 모드 바퀴(28b `booking-mode-wheel`)도 같은 컴포저블을 쓴다.
  • 주행 중 화면과 무관(홈 = 정차). 운전자 문장 숫자 0 — 점은 숫자가 아니다.
