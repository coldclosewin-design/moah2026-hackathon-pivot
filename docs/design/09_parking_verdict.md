출처: `docs/놓치지 말고 확인해야 할 사항.md` 1번 — "단순한 센서·이동 횟수가 아니라 좀 더 **기능적으로** 유저가 납득할 판단 기준 혹은 도움이 될 지표". 기준 `main` 338c761, `scoring/ParkingScorer.kt`·`PathReconstructor.kt`·`feature/lesson/RemarkPool.kt`.

## 0. 결론 먼저

지금 점수는 **"이상값에서 횟수를 빼는 식"** 이라 운전자에게는 "왜 60점이지?" 가 되고, 서두 문장은 (감사 뒤) "연습을 마쳤어요" 류로 중립이 돼 **잘했는지 못했는지를 말해 주지 않는다**. 운전자가 주차를 스스로 판단하는 기준은 넷이다 — ① **한 번에 들어갔나** ② **방향이 맞게 섰나** ③ **깔끔하게 마무리했나** ④ **안전했나**. 넷 다 **지금 신호로 계산할 수 있다**(②만 추정). 제안은 이 **네 가지 판정(`ParkingVerdict`)** 을 채점기 옆에 두고, 운전자 화면(Done·Report 요약)은 점수 대신 이 넷을 보여 주며, 0~100 점수는 `자세히 보기`·진단서에만 남기는 것이다. 점수·채점표·시나리오 고정값(60/55·100/100)은 **그대로** — 판정은 같은 지표에서 **파생**되므로 테스트·`emu_flow` 가 깨지지 않는다.

## 1. 지금 기준 (사실)

`ParkingRubric` 기본값 — 숙련·안전 각 100 에서 뺀다:

| 축 | 지표(신호) | 이상값 | 감점 | 못한 주차 시나리오 | 잘한 주차 |
|---|---|---|---|---|---|
| 숙련 | 이동 구간 수(속도) | 2 | 초과 1구간 −8 | 4 → −16 | 2 |
| 숙련 | 조향 되돌림(조향각) | 1 | 초과 1회 −6 | 3 → −12 | 1 |
| 숙련 | R↔D 전환(기어) | 0 | 1회 −6 | 2 → −12 | 0 |
| 숙련 | 마지막 기어 P 아님 | — | −5 | P | P |
| 숙련 | 총 시간 > 60 s | 60 s | 10 s 당 −2 | 44 s → 0 | 0 |
| 안전 | 급가속·급제동(속도 미분) | 0 | 1회 −15 | 1 → −15 | 0 |
| 안전 | 근접 경고(뒤 거리 < 40 cm · IsWarning) | 0 | 1회 −10 | 1 → −10 | 0 |
| 안전 | 첫 이동 전 벨트 없음 | — | −20 | −20 | ✓ |
| | **결과** | | | **60 / 55** | **100 / 100** |

밴드(`ScoreBand.of(skill)`): ≥90 EXCELLENT · ≥70 GOOD · ≥50 OK · 그 밖 ROUGH → 서두 문장 풀 선택. 운전자에게 들리는 것은 서두 + 조언 두 문장, 점수는 `자세히 보기`.

**왜 납득이 안 되나**
1. 뺄셈의 단위(−8·−6)가 운전자 경험과 대응하지 않는다. "되돌림 2번 더" 가 −12 라는 걸 운전자가 느낄 수 없다.
2. 판정이 없다. 운전자는 "들어갔나 / 다시 뺐나 / 똑바로 섰나" 로 판단하는데, 앱은 그 질문에 답하지 않고 횟수만 센다.
3. 카메라가 없어 "칸 안 위치" 를 모른다고 정직하게 두는 건 맞지만, **방향(헤딩)은 조향각·기어·속도로 이미 추정하고 있다**(`PathReconstructor`, Done 의 궤적). 그걸 판정에 안 쓴다.
4. 감사 뒤 서두가 중립이 되어 "잘했다/아쉽다" 가 사라졌다 — 감사가 금지한 건 **측정 안 한 사실의 단정**이지, 측정된 사실의 판정이 아니다. "한 번에 들어갔어요" 는 이동 구간 ≤ 2 · 기어 전환 0 이면 **측정된 사실**이다.

## 2. 제안 — 네 가지 판정 `ParkingVerdict` (전부 지금 신호로)

| # | 운전자의 질문 | 판정 | 계산(이미 있는 지표) | 신호 없으면 |
|---|---|---|---|---|
| ① | **한 번에 들어갔나** | `ONE_GO` 한 번에 / `ONE_FIX` 한 번 다시 / `MANY` 여러 번 | 이동 구간 ≤ 2 **그리고** R↔D 전환 0 → 한 번에 · 구간 3~4 또는 전환 1~2 → 한 번 다시 · 그 밖 → 여러 번 | 기어 없으면 구간만으로 |
| ② | **방향이 맞게 섰나**(추정) | `ALIGNED` 맞게 / `SLIGHT` 조금 틀어짐 / `OFF` 많이 틀어짐 / `UNKNOWN` | 궤적 끝 헤딩 − 시작 헤딩: 후면 직각은 목표 **90°**. |편차| ≤ 10° 맞게 · ≤ 25° 조금 · 그 밖 많이. **"신호로 추정"** 꼬리표 필수 | 조향각 없으면 `UNKNOWN`(미측정) |
| ③ | **깔끔하게 마무리했나** | `CLEAN` / `LOOSE` | 정차 **그리고** 마지막 기어 P **그리고** 마지막 조향각 |θ| < 30°(핸들 중립) | 기어·조향 없으면 정차만 |
| ④ | **안전했나** | `SAFE` / `WATCH` / `UNSAFE` | 급조작 0 · 근접 0 · 벨트 ✓ → 안전 · 하나 → 주의 · 둘 이상 또는 벨트 ✗ → 위험 | 미측정 항목은 세지 않음 |

운전자에게 보이는 것: Done 왼쪽(또는 Report 요약)에 **네 줄** — `한 번에 들어갔어요 ✓ · 방향은 맞게 섰어요(추정) ✓ · 마무리는 깔끔했어요 ✓ · 안전했어요 ✓`. 못한 주차 시나리오면 `한 번 다시 들어갔어요 △ · 방향 조금 틀어졌어요(추정) △ · 마무리 깔끔 ✓ · 주의할 게 있었어요 △(벨트·급제동·근접)`. 숫자 0, 문장은 측정 사실만, 미측정은 `—`.

**점수와의 관계**: 밴드를 뺄셈 점수 대신 판정 수로 정한다 — ①·③·④ 가 전부 최상 → EXCELLENT, ① 한 번 다시 + ④ 주의 이하 → GOOD, ① 여러 번 또는 ④ 위험 → OK/ROUGH(②는 추정이라 밴드에 안 넣음, 문장에만). 0~100 점수는 그대로 계산해 `자세히 보기`·진단서·기관용으로 남긴다. "지난번보다"(`ParkingDelta`)도 그대로 — 조언 선택의 근거.

**서두 문장이 다시 살아난다**: 서두 풀을 판정별로 묶으면 "한 번에 들어갔어요." 같은 문장이 **근거 있는** 긍정이 된다(감사 A3-04 와 충돌하지 않음 — 측정된 것만 말함).

## 3.5 과제별 사양 (10/3, 전면 직각 주차)

판정 ①~④ 의 규칙·경계는 과제가 달라도 같다. 다른 것은 `scoring/ParkingSpec` 셋 — **진입 기어**(후면 R·전면 D: 힌트·조언 문장의 방향과 화면 도식의 위아래), **목표 각**(직각 주차 둘 다 90°, ② 의 기준), **구독 키**(전면은 뒤 거리 없이 7). ② 방향은 `abs(abs(Δheading) − target)` 이라 앞으로 도는 원호(헤딩 음수)에도 그대로 쓴다. 평행·사선 주차를 붙일 때 목표 각이나 구간 구조가 다르면 그때 사양을 늘린다(`ParkingSpecTest`).
