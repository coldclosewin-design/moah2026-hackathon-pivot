라운드 27 · 5 움직임 언어 — 버튼 채움 · 선택 모핑 · 카드 쌓기 · 하프톤 차 · 기호

이 페이지는 HTML 로 열면 실제로 움직인다(CSS @keyframes). PNG 에는 움직임이 안 보이므로 각 안마다 같은 움직임을 프레임 띠(0 / 1/3 / 2/3 / 끝)로 멈춰 그렸다 — 프레임은 같은 애니메이션을 그 시각에 일시정지한 것이라 실제와 똑같다. 모든 안은 같은 문구 · 같은 부품(2 부품 문법의 P1/P8 재질)을 쓴다.

움직임 시안은 1/2 크기 — 실제 128 dp 버튼 → 64 px · 실제 화면은 약 2배프레임 띠 아래 숫자 = 시작부터 ms시간 · 가속 곡선은 Compose 에 그대로 옮길 값
짧게 160–200 ms누름 반응 · 놓음 · 페이드. cubic-bezier(0,0,.2,1)
기본 280 ms선택 알약 이동. cubic-bezier(.3,1.25,.5,1) — 3 % 지나침 하나만 허용
강조 360–480 ms채움 · 카드 등장. 들어옴 cubic-bezier(.2,.9,.25,1) · 나감 cubic-bezier(.4,0,1,1)
주행 중 규칙장식 움직임 0 · 화면 전환은 즉시 · 접근성 “움직임 줄이기” 면 모든 전환을 0 ms 로

(a) 버튼 채움 — 핀 A테두리 알약 + 왼쪽 원 화살표 → 원이 커지며 검은 면이 알약을 채우고 글자가 흰색으로 뒤집힘 → 놓으면 되돌아감

세 안 모두 같은 원리: 검은 판(흰 글자)을 원/사각 클립으로 가렸다가 넓힌다. 그래서 글자는 채움 경계에서 정확히 반으로 갈라져 뒤집힌다. 움직임 시안은 1/2 크기(실제 128 dp 버튼 → 64 px). 프레임 띠의 시간은 누름 시작 기준.

A1

원이 번진다공수 작음추천

원이 왼쪽에서 번져 알약 전체를 덮는다. 사용자 지시와 가장 같다.

  • 누름: 360 ms cubic-bezier(.2,.8,.2,1)(빠르게 시작 · 부드럽게 멈춤)
  • 놓음: 260 ms cubic-bezier(.4,0,.6,1) 역재생
  • Compose: animateFloatAsState(radius) + drawWithContent { clipPath(원) { 검은 판 · 흰 글자 } } — 버튼 하나에 한 번만 짜면 끝

  • 글자 색: 알약과 같은 클립으로 흰/회색이 갈림(따로 색 애니메이션 없음)

(c) 카드 쌓기 — 핀 B정보가 많은 시트(과제 시트 · 시험장 · 자세히 보기 · 진단서 · 지식 해설)에서 흰 카드가 아래에서 올라와 앞 카드 위에 겹친다

큰 문장 속 한 낱말은 회색으로 약하게, 문장 안에 작은 아이콘 알약(노란 원 + 막대 기호). 정차 화면 전용 — 주행 중에는 시트가 열리지 않는다. 1/2 크기.

C1

계단처럼 겹쳐 오르기공수 중간추천

세 장이 차례로 올라와 계단처럼 겹친다. 뒤 카드는 아주 살짝 작아지고 어두워져 깊이가 생긴다.

  • 카드마다 420 ms cubic-bezier(.2,.9,.25,1), 간격 160 ms → 전체 740 ms
  • 뒤 카드 0.965 배 · 밝기 96 % (같은 420 ms)
  • 닫힘: 한꺼번에 아래로 300 ms cubic-bezier(.4,0,1,1)
  • Compose: 카드마다 AnimatedVisibility(slideInVertically + 지연) + graphicsLayer(scale) — 시트 구조를 카드 단위로 나눠야 해 중간

(d) 하프톤 점 차 — 핀 C크기가 다른 점의 격자로 그린 차 · 점이 앞에서 뒤로 커졌다 작아지며(파도) 달린다

점 크기 = 명암. 유리는 작은 점(밝게), 차체 아래쪽은 큰 점(어둡게), 전조등 · 후미등은 가장 큰 점. 점 맥동은 900 ms ease-in-out, 앞 → 뒤로 열을 100 ms 씩 늦춰 “달리는” 파도. 실제 앱은 점 좌표를 미리 계산해 Canvas 로 그린다(점 150~400 개, 비트맵 없음).

D1

주차 궤적 — 위에서공수 중간추천

지금 주차 중 왼쪽 판의 “위에서 본 차 + 궤적” 을 점으로. 전진 → 멈춤(R) → 후진으로 목표 칸에 들어간다. 칸 선 · 벽도 점선.

  • 6 s 시연 루프: 전진 2.1 s cubic-bezier(.45,0,.4,1) · 정지 0.6 s · 후진 2.4 s cubic-bezier(.45,0,.25,1)
  • 실제 앱에선 시간 대신 조향각 · 속도 신호가 위치를 민다(시뮬이면 배지 “시뮬레이션”)
  • Compose: Canvas + PathMeasure.getPosTan + 점 배열 drawCircle — 중간
  • 칸에 반듯이 들어갔는지는 모른다 — 점 차는 “예상 궤적” 이지 카메라가 아님(정직성)

Compose 구현rememberInfiniteTransition + Canvas 선 그리기(PathMeasure.getSegment로 “그려지는 선”). 기호 13개 × 약 20분 — 중간. 대안: AnimatedVectorDrawable(XML) — 비슷.
정직성실신호 · 시뮬레이션 · 미측정 타일은 정적 배지(● ◐ ○)와 같은 모양을 쓴다 — 움직임을 꺼도(접근성) 모양으로 구분된다.
추천 · 마감 10/9 기준 공수 순서

A1 원이 번짐 + B1 미끄러지는 돌 + E1 기호(우선 6개) 먼저, D1 주차 점 차는 그다음

묶음추천 안왜공수
(a) 버튼A1 원이 번진다 추천사용자 지시(핀 A) 그대로. 컴포저블 하나(FillButton)로 시작 · 다 됐어요 · 한 번 더 · 메인으로 전부.작음
(b) 선택B1 미끄러지는 돌 추천선택이 늘 한 칸만 검다 — 모호한 순간 없음. 트랙 · 모드 · 단계 번호에 한 번에.작음
(e) 기호E1 검은 돌 타일 추천2 부품 문법 P1/P8 과 같은 재질. 우선 6개: 음성 안내 중 · 실신호 · 시뮬레이션 · 미측정 · 체크 · 잠금 → 나머지 7개는 시간 되면.작음(6개) → 중간(13개)
(d) 점 차D1 주차 궤적 추천 → D3 홈시연 본편(후면 직각 주차) 화면이 바로 바뀌어 보인다. D2 는 D1 컴포저블을 재사용하므로 거의 공짜.중간
(c) 카드C1 계단처럼 겹쳐 오르기시트 구조를 카드 단위로 쪼개야 해 가장 손이 많이 간다 — 마감 뒤 또는 진단서 하나에만 먼저.중간
