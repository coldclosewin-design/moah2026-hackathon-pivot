홈 화면 · 코치와 대화해서 과제로 가기 — 시안 여덟 가지

지금 홈은 "마지막 설정을 바로 시작" 과 "과제·모드 바꾸기" 두 길뿐이다. 코치와 짧은 대화로 원하는 과제 카드 또는 예약한 시험장까지 가는 세 번째 길을 여덟 가지 모양으로 그렸다. 모두 정차 중 화면(잠금 없음)이고, 지금은 탭으로 답하고 음성은 자리만 남긴다.

사용자 피드백 (원문) #홈화면_AI대화 — 현재 홈화면은 마지막으로 설정한 (예. 후면 직각 주차, 가이드 모드) 등을 바로 시작 하는 것과 과제 모드 바꾸기 밖에 없는데 / AI 대화를 통해 해당 카드에 접근 하는 UX도 추가 하고 싶은데 방식 디자인 등 5~10가지 정도 제안을 받아서 적용해보고 싶어. / 흐름은 음성 없이 기존 처럼 클릭으로 진행해도 되고 음성으로도 현재 하고 싶은 예약 또는 예약된 곳으로 가서 무슨 진행을 하고 싶은지 간략한 대화를 통해서 진행하는 방향을 기획하고 있어
아래 화면은 모두 실제의 1/3 (853 × 423) — 실제 화면은 약 3배
Ink Paper Periwinkle Lavender Signal · 모든 시안이 같은 상황: 서초 시험장 주차 코스가 예약돼 있고, 마지막 설정은 후면 직각 주차 · 가이드 모드. 대화의 목적지는 "예약한 시험장에서 모의시험" 또는 "주차 카드"
전제 하나 · 정차 중홈은 차가 서 있을 때만 보인다. 잠금 없음, 터치 가능. 그래도 글자는 본문 40 dp 아래로 내리지 않는다.
전제 둘 · 음성 인식은 아직STT 는 사내 확인 전. 모든 대화는 답 칩(탭) 으로 먼저 완결되고, 마이크는 "준비 중" 자리만 남겨 나중에 켠다.
전제 셋 · 코치는 꺼질 수 있다Cloud Copilot 이 오프라인이면 코치 문장은 시드 문장으로 대체된다. 대화의 분기는 규칙(칩 → 과제·모드)이 하고, AI 는 말투만 바꾼다.

지금

제안 하나 · 길 둘

코치가 제안 하나를 제목으로 말하고, 운전자는 `시작` 또는 `과제·모드 바꾸기` 둘 중 하나를 누른다. 예약이 있으면 위에 `예약 · 서초 14:00 · 주차 3종` 배지가 붙는다.

보이는 문제

  • 제안이 마음에 안 들면 바로 시트로 가서 분류·카드·모드를 손으로 골라야 한다 — "말로 한마디" 가 없다
  • 예약 배지는 정보만 보여 주고 누를 수 없다 — "거기 가서 뭘 할지" 를 홈에서 정할 길이 없다
  • `AI 코치 · 연결됨` 줄이 맨 아래 있지만 홈에서 코치가 하는 일은 제목 한 줄뿐이라 "대화 상대" 로 느껴지지 않는다
  • 오른쪽 아래가 비어 있다(링크 아래 약 450 dp) — 대화 요소가 들어갈 자리는 충분하다

이미 있는 것 · `LessonViewModel.subtitle`(마지막 TTS 문장) · `CoachPort`(폴백 포함) · 과제 시트(분류·카드·모드 선택 상태) · 예약 상태(배지) — 시안은 이 넷을 어떻게 잇느냐의 차이다.

시안 A

알약 (Pill → Sheet)

홈에는 `과제·모드 바꾸기` 옆 보조 알약 `코치에게 말하기` 하나만 더한다. 누르면 오른쪽 면이 대화 시트로 바뀌고, 코치 말풍선 하나 + 답 칩 셋이 번갈아 나온다.

장점

  • 홈 모양이 거의 그대로 — 알약 하나라 기존 계측·캡처에 영향이 작다
  • 대화가 자기 화면을 가져서 두세 번 주고받아도 홈이 어지럽지 않다
  • 마이크 자리가 시트 안에 자연스럽게 생긴다(지금은 흐림, 나중에 켬)

주의점

  • 새 화면 하나(대화 시트) — 상태기계에는 안 들어가고 Setup 안의 보조 화면으로 둔다
  • STT 의존 없음. 코치 오프라인이면 질문·되묻기가 시드 문장 두 개로 고정
  • "홈 → 시트 → 홈" 왕복이 한 번 더 생겨 `과제·모드 바꾸기` 와 역할이 겹쳐 보일 수 있다 — 알약 문구로 구분("말하기" vs "바꾸기")

시안 B

질문 (Question)

홈 제목이 "오늘은 뭘 해 볼까요?" 질문이 되고, 바로 아래 답 칩 셋이 놓인다. 칩을 고르면 과제·모드 줄과 이유가 바뀌고 같은 `시작` 을 누른다. 대화가 홈 안에서 끝난다.

장점

  • 새 화면 0 — 홈 한 장에 질문과 답이 함께 있어 가장 빠르다(탭 두 번)
  • 첫 칩이 미리 선택돼 있어 "그냥 시작" 하는 사람은 전과 똑같이 `시작` 만 누른다
  • 칩 줄이 되묻기로 바뀌는 규칙이 단순해 Fake 로도 완결

주의점

  • 제목이 질문으로 고정되면 "오늘은 가볍게, 주차부터" 같은 코치 제안 문장의 자리가 없어진다 — 제안은 첫 칩 + 이유 줄로 옮겨야 한다
  • 칩 셋이 제목과 과제·모드 줄 사이에 끼어 홈이 한 층 빽빽해진다(실제 화면 기준 칩 높이 90 dp)
  • 되묻기가 두 번 이상 필요한 경우(분류 → 카드 → 모드)는 못 담는다 — 그때는 `과제·모드 바꾸기` 로

시안 C

띠 (Band)

왼쪽 일러스트 아래를 Ink 띠로 잘라 "오늘 뭐 할까요?" + 마이크 + 글자 칩을 둔다. 오른쪽은 코치의 제안을 담은 결과 카드 한 장이고, 띠에서 고를 때마다 카드가 바뀐다.

장점

  • "묻는 곳(왼쪽) / 답이 나오는 곳(오른쪽)" 이 면으로 갈라져 대화의 구조가 그림으로 읽힌다
  • 왼쪽 Ink 띠가 포스터 구도(큰 면 분할)에 가장 잘 맞고, 마이크의 제자리가 분명하다
  • 결과가 카드라 "코치가 카드를 열어 보여 준다" 는 느낌이 제일 세다

주의점

  • 새 화면은 0 이지만 왼쪽 패널을 자르므로 홈 레이아웃 변경이 가장 크다(일러스트를 위로 밀어 올려야 함)
  • Ink 위 칩은 Lavender 테두리뿐이라 선택 표시를 Signal 채움으로 해야 보인다
  • 오른쪽 제목이 카드 안으로 들어가 글자가 한 단계 작아진다(약 66 dp) — 눈썹·이유와의 대비를 다시 잡아야 한다

시안 D

예약 카드 (Reserved)

예약이 있을 때만 홈에 "예약한 서초 시험장 · 주차 3종 — 거기서 할 걸 골라요" 카드가 뜬다. 코치가 두 선택지(코스 연습 / 모의시험)를 칩으로 내밀고, 고르면 과제·모드 줄이 바뀐다.

장점

  • 피드백의 핵심 장면("예약된 곳으로 가서 무슨 진행을 하고 싶은지") 을 가장 직접적으로 푼다 — 누를 수 없던 예약 배지가 카드가 된다
  • AI 가 없어도 성립 — 카드 문구는 예약 데이터(시험장·코스)에서 그대로 나오고 칩 → 모드 매핑은 규칙
  • 새 화면 0, 새 요소는 카드 하나 — 시험장 시트의 미니 지도를 재사용

주의점

  • 예약이 없는 날은 아무 대화도 없다 — "주차 카드로 가기" 같은 일반 대화는 못 담는다(A·H 와 짝지어야 함)
  • `코스 연습` 이 가이드인지 힌트인지는 프로필(처음 하는 과제면 가이드)로 정한다는 규칙을 이유 줄에 써 줘야 한다
  • 예약 배지(위)와 카드(아래)가 같은 정보를 두 번 보여 준다 — 배지를 카드로 흡수하는 쪽이 깔끔

코치 캐릭터도 말풍선도 없다. 홈 맨 아래 자막 한 줄(본문 40 dp)이 코치의 질문이고, 그 아래 답 알약 둘. 한 턴 = 문장 하나 + 둘 중 하나. 자막은 TTS 가 읽는 문장과 같다.

장점

  • `LessonViewModel.subtitle` 이 이미 있다 — 홈에서도 같은 자막 줄을 쓰면 새 요소는 알약 둘뿐
  • 주행 중 화면(Driving 의 자막)과 같은 문법이라 앱 전체가 "코치는 자막으로 말한다" 한 규칙이 된다
  • 둘 중 하나라 운전석에서 가장 읽기 쉽고, 나중에 음성이 와도 "둘 중 하나 말하기" 인식이 쉽다

  • 이지선다라 턴이 늘어난다 — 네 분류(주차·주행·점검·지식)까지 가려면 세 턴 이상. 그 경우 `과제·모드 바꾸기` 로 넘긴다
  • 자막이 홈 아래 `AI 코치` 줄 자리를 차지해 상태 줄을 한 단계 더 작게 내려야 한다
  • 코치 오프라인이면 질문 문장이 시드로 고정되어 "대화" 라기보다 "이분기 메뉴" 처럼 느껴질 수 있다

음성 (Voice-first)

홈 오른쪽 아래 큰 마이크 알약. 누르면 듣는 중 파형이 나오고, 인식된 문장이 제목 자리에 들어오며, 코치가 과제 카드를 "열어 보여" 준다(카드 미리보기가 홈에 떠오름). 음성은 나중, 지금은 탭 칩으로 같은 흐름.

장점

  • 피드백의 "음성으로도" 를 화면이 먼저 약속한다 — 시연 영상에서 가장 그림이 된다
  • 인식 문장이 제목 자리에 오면 "내 말을 알아들었다" 는 확인이 바로 보인다
  • 카드 미리보기는 과제 카드 C 그대로라 새 그림이 없다

주의점

  • STT 의존이 가장 크다 — 지금은 탭 경로가 본체여야 하고, 탭일 때 "들은 말" 자리를 무엇으로 채울지(고른 칩 문장) 정해야 한다
  • 인식 문장 → 과제·모드 매핑은 AI 가 아니라 규칙(키워드 → 카드)이어야 오프라인에서도 산다. 못 알아들으면 시드 되묻기 한 번 뒤 칩으로 폴백
  • 듣는 중 · 미리보기 두 상태가 홈에 겹쳐 레이아웃이 가장 복잡하다(난이도 상). 제목이 사라지는 순간이 있어 계측도 손봐야 한다

시안 H

하이브리드 (Reuse)

`시작 →` 옆에 작은 보조 알약 `다른 걸 할래요`. 누르면 코치가 질문 하나만 하고, 답 칩에 따라 기존 과제 시트 또는 시험장 시트가 해당 분류·카드·모드가 미리 선택된 상태로 열린다. 새 화면 0.

장점

  • 대화는 "한 질문 → 시트 미리 선택" 뿐이라 가장 가볍다 — 시트가 이미 모든 선택 UI 를 갖고 있으니 대화는 지름길만 맡는다
  • 틀리게 알아들어도 시트 안에서 바로 고치면 된다 — 되묻기 턴이 필요 없다
  • 칩 → (분류, 카드, 모드) 매핑이 규칙이라 코치 오프라인에서도 질문 문장만 시드로 바꾸면 끝. 마이크는 같은 질문 풍선 안에 나중에 붙인다
  • 예약이 있으면 칩 첫 자리에 `예약한 시험장으로` 가 오고, 없으면 그 칩만 빠진다(D 의 장점 흡수)

주의점

  • `시작` 알약 폭이 줄어든다(실제 약 720 dp → 여전히 브리프 하한 이상). 보조 알약이 `시작` 왼쪽에 붙어 오누름 위험 — 간격 36 dp 이상
  • 시트가 "미리 선택된 채" 열리는 진입 파라미터(분류·카드·모드·시험장)가 ViewModel 에 필요 — 작지만 Claude 영역 변경
  • 질문 풍선이 링크(`과제·모드 바꾸기`)를 아래로 밀어 홈 하단이 살짝 빽빽해진다 — 풍선은 누른 뒤에만 펼침
