# 라운드 6·동승자 영상 피드백 → 반영 계획 (2026-09-28, 라운드 7)

사용자가 라운드 6 + 동승자 빌드(`main = 697f7c0`, `build/demo-companion.mp4`)를 보고 준 피드백 6건. 형식은 `03`·`04` 와 같다. 원문은 하단.

## 0. 성격

세 종류가 섞여 있다. ① **바로 고칠 화면**(지식 테스트 표시·중간 종료, 조향 바퀴·점선) ② **뺄 것**(동승자 공유 — 만든 지 하루 만에 "운전자 입장에서 불필요") ③ **기획이 먼저인 것**(출발 전 점검 확장, 시험장 예약 시스템 — 지금은 카드 한 장). ①②는 라운드 7 로 발주하고, ③은 이 문서 §2 의 제안을 사용자가 고른 뒤 발주한다.

## 2. 기획 제안 (사용자 결정)

### 2.1 출발 전 점검 확장 (D1)

지금은 벨트 → P 확인 → 브레이크 밟고 시동, 3단계 8 s. 신호 스텁에 이미 있는 것으로 넓히면 **7단계**가 된다(새 VSS 경로 없음 → 사내 이관 위험 없음):

| # | 단계 | 확인 신호 | 채점(숙련/안전) |
|---|---|---|---|
| 1 | 운전석 도어 닫기 | `Door.Row1.DriverSide.IsOpen` = false | 안전: 도어 열린 채 시동 -30 |
| 2 | 안전벨트 | `Seat.Row1.DriverSide.IsBelted` | 기존 |
| 3 | 기어 P 확인 | `Transmission.SelectedGear` | 기존 |
| 4 | 브레이크 밟고 시동 | `Brake.PedalPosition` > 0 → `LowVoltageSystemState` ON | 숙련: 브레이크 없이 시동 -20(신호 있을 때만) |
| 5 | 좌 방향지시등 켜 보기 | `DirectionIndicator.Left.IsSignaling` | 숙련: 건너뜀 -10 |
| 6 | 우 방향지시등 켜 보기 | `DirectionIndicator.Right.IsSignaling` | 숙련: 건너뜀 -10 |
| 7 | 비상등 켰다 끄기 | `Hazard.IsSignaling` true → false | 숙련: 건너뜀 -10 |

- 순서 규칙은 지금과 같다(벨트가 시동보다 먼저). 미측정 신호는 감점 없이 "확인할 수 없었어요".
- Fake 시나리오 2벌 갱신(잘한 점검 ~14 s / 못한 점검 ~20 s: 도어 열린 채 시동 + 지시등 건너뜀). `ChecklistScenarioTest` 고정값 갱신.
- 화면(Codex): 점검 `Maneuver` 칩 3 → **7**(도어·벨트·P·브레이크/시동·좌·우·비상등, 미측정 회색), `Done`·`Report` 행도 항목 수만큼.
- **결정**: 7단계 그대로 / 5단계(지시등·비상등 중 하나만) / 다른 항목 추가(사이드미러·시트는 신호가 없어 "확인했어요" 버튼이 필요 — 정차 중이라 허용 가능하지만 자기 신고라 정직 원칙에서 약함).

### 2.2 시험장 예약 시스템 (D3)

지금은 시트 아래 카드 한 장("제휴 도로주행시험장 (서초) · 오늘 14:00–15:00 · 코스 B"). 실제 연계 없이도 **흐름**을 만들면 제품 축 하나(§3.3 장소)가 선다:

| 단계 | 화면 | 데이터(시드) |
|---|---|---|
| ① 목록 | Setup 시트 하단 `제휴 시험장` → 시험장 3곳 카드(이름·거리·코스 종류·오늘 빈 시간 수 — 숫자는 정차 중 선택 화면이라 허용) | `Venue(id, name, distanceKm, courses: List<Course>, slots: List<Slot>)` ×3(서초·강남·분당, 시드 좌표는 U3) |
| ② 시간·코스 | 시험장 카드 → 시간대 칩(오늘 3개) + 코스 칩(주차 3종 / 도로 A / 도로 B) | `Slot(start, end, available)`, `Course(id, title, tasks: List<taskId>)` |
| ③ 확인 | `예약` 주 버튼 → 확인 카드 + "예시입니다 — 실제 예약 연계 없음" | `Reservation(venueId, slot, courseId, madeAt)` → `ProgressStore.reservation` |
| ④ Setup 배지 | 첫 화면 프로필 눈썹 위에 `예약 · 서초 14:00 · 코스 B` + 제안 과제가 그 코스의 과제로 | `ModeAdvisor.suggestTask` 가 예약 코스의 READY 과제를 우선 |
| ⑤ 세션·리포트 | 예약 시간대에 시작한 세션은 Report 눈썹에 `제휴 시험장 세션`, 진단서 혜택에 `대여료 할인 적용 예시` | `LessonReport.venue: Venue?` |
| ⑥ 취소 | 확인 카드에서 `취소` | `ProgressStore.reservation = null` |

- 상태기계 진입점: `reserve(venueId, slotId, courseId)`·`cancelReservation()`(Setup 에서만). Claude A: 모델·시드·진입점·제안 우선순위·리포트 필드 + 테스트. Codex B: 화면 ①~④ + 계측.
- **결정**: 범위 (가) ①~③ 예약 흐름만 / (나) + ④ Setup 배지·과제 제안 / (다) + ⑤ 리포트·혜택 연동. **제안 (나)** — 시연에서 "예약 → 그 코스로 시작" 이 한 장면으로 보이고, ⑤는 진단서 예시와 겹친다.
- 시연 대본에는 Setup 15 s 안에 "예약 카드가 있는 걸 스쳐 보여 준다" 정도로(0:10). 본편 흐름은 불변.

### D2 · 동승자 제거 범위

결정은 났다(제거). 범위는 Claude 판단: **전부** — 화면(Codex, 라운드 7) → 모델·코치·상태기계·시드·`emu_flow` 단계(Claude). 되돌리기는 git 이력(PR #40~#43)으로 가능. 대본·컷·덱은 12c 이전으로.
