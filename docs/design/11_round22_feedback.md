- 지금 화면: 눈썹 `진단서` → "예시입니다 — 실제 전송·계약은 없습니다" → 왼쪽 `공유 범위` 라디오 셋(총점만/항목별/원시 신호) · 오른쪽 `예상 혜택` 세 줄 → 글자 링크 `공유 예시 보기`(토스트만) → `← 돌아가기` · `다시 시작 →` 가 거의 붙어 있음(`ReportScreen.kt` `CertificateContent` + 하단 Row `SpaceBetween` 인데 왼쪽 알약 폭이 커서 간격이 좁다).

### 5 "다 됐어요" 알약 점프 (B)

> 어느 진행이든 '다됐어요' 알약을 누르면 잠깐 아래에 텍스트가 있다가 해당 텍스트가 없어지면서 알약이 부자연스럽게 내려옴 조치 필요

- 원인(코드로 확인): `DoneScreen.kt` 66~78행 — 오른쪽 열은 `[제목] [멘트 Box weight(1f)] [한 번 더 알약 Row] [SpeechFooter]` 순서. 멘트(`record.remark`)는 Done 진입 **전에** 계산되므로 멘트는 처음부터 있다. 문제는 맨 아래 `SpeechFooter(subtitle)` — Done 에 들어온 순간 `subtitle` 은 아직 Maneuver 의 마지막 자막("다 되셨나요? 다 됐으면 버튼을 눌러 주세요.")이라 푸터가 그려지고, 곧 `tts.speak(remark)` 로 자막이 멘트와 같아지면 `takeUnless` 조건으로 푸터가 **사라진다** → weight(1f) Box 가 늘어나 알약 Row 가 아래로 밀린다. 점검 Done·코스 Done 도 같은 구조. 발주 ②: 푸터 자리를 고정 높이로 잡아 두고(비면 투명) 알약은 움직이지 않게, 또는 Done 에서는 묵은 자막을 아예 그리지 않는다(멘트가 곧 자막이므로). Maneuver 의 힌트 소거(4 s 뒤 `visibleHint = null`)는 weight(1f) 열 안이라 알약이 안 움직이지만 같은 PR 에서 눈으로 확인.

```
                                                     └ 예약 → ──▶ 예약 확인 카드(시험장 · 시간 · 코스 · 취소)

홈(예약 뒤): 눈썹 `예약 · 서초 시험장 14:00 주차 3종`, 제안 과제 = 예약 코스의 첫 과제(가이드/힌트는 기록으로)
```

- 예약은 **하나만**, 인메모리(앱 재시작 시 사라짐 — 시연은 매번 다시 예약, `emu_flow.sh RESERVE=1`).
- 예약한 시험장 카드를 다시 누르면 확인 카드. 다른 시험장을 고르면 새 예약으로 바뀐다(취소 없이 덮어씀).
- 빈자리: 홈에서 예약으로 바로 가는 길이 없고, 예약과 "오늘 할 과제" 의 연결이 눈썹 한 줄뿐 — 9 번 시안이 다룬다.

## 3. 신호 출처 배지가 꼭 필요한가 — 의견

- **리포트 요약 페이지에는 필요하다.** 이 앱의 제품 원칙(AGENTS: "무엇이 실신호이고 무엇이 시뮬레이션인지 화면·리포트에 정직하게 구분")이고, 덱 6장의 핵심 장면이며, 사내 Real 빌드에서 같은 커밋이 `실신호 7 · 시뮬레이션 1` 로 바뀌는 것을 **심사위원이 그 자리에서 보는** 유일한 수단이다. 사내 검증 #3 PASS 기준도 이 배지다(`tools/inhouse_check.sh`).
- **자세히 보기·진단서에서는 지금 크기일 필요가 없다.** 거기서는 회차 카드가 주인공이고, 미측정은 카드 안 항목에 `미측정` 글자로 이미 드러난다. 두 페이지에서는 32 dp 한 줄(`신호 출처 · 실신호 0 · 시뮬레이션 8 · 미측정 0`)로 줄이거나 빼도 원칙이 깨지지 않는다.
- 단, "주차 과정만 측정했어요." 같은 **측정 범위 문장은 진단서에 남기는 편이** 좋다 — 진단서는 밖으로 나가는 것을 전제로 하는 화면이라 "무엇을 재지 않았는지" 가 거기서 더 중요하다.
- 추천: 요약 = 지금 그대로 / 자세히 보기 = 한 줄 / 진단서 = 한 줄 + 측정 범위 문장. 시안 `6-details-badge.html` B.

## 4. 프로필 — 구현 계획 초안과 질문

### 지금 있는 것
- 모델 `Profile(name, statement, observation)` — 진술 5(면허 연도 · 마지막 운전 · 차종 · 운전이 필요한 일 · 제일 무서운 상황) + 관측(연습 횟수 · 평균 구간 · 평균 조향 왕복 · 급조작 · 약한 과제). 질문 5개는 `SeedCatalog.profileQuestions` 에 이미 있다.
- 쓰는 곳: 홈 눈썹 한 줄(`profileLine`) · 과제 제안(`ModeAdvisor` — 공포 → 약점 → 첫 쉬운 것) · 회차 멘트 태그(`rusty`) · Cloud Copilot 프롬프트의 운전자 줄.
- 없는 것: 입력 화면, 저장(앱 재시작 뒤 유지), 여러 운전자, 초기화.

### 단계 (각 단계가 그 자체로 시연 가능)
| 단계 | 내용 | 누가 |
|---|---|---|
| P1 모델 | `ProfileStatement` 답을 **칩 값**(열거형: 면허 "작년/몇 년 전/십 년 넘게", 마지막 운전 "최근/몇 달 전/몇 년 전/기억 안 남", 차종 "경차/준중형/중형 SUV/대형", 목표 4~5, 공포 4~5)으로 바꾸고 자유 입력은 뒤로. `ProfileStore`(JSON 한 파일, 앱 내부 저장소) + `reset`. 시연 프로필은 관리자 프리셋 | Claude |
| P2 화면 | 시안 `7-profile.html` 에서 고른 흐름(온보딩 / 홈 눈썹 시트 / 코치 대화형 / 점진형) | Codex |
| P3 연결 | 제안 문장·회차 멘트·Copilot 프롬프트가 새 값을 쓰도록, 관측 프로필 표시(선택) | Claude |
| P4 다중 운전자(선택) | 프로필 둘 이상 + 홈에서 바꾸기 — 가족 차 시나리오 | 결정 뒤 |

### 질의응답으로 정할 것 (추천 기본값)
1. 이름을 받을지 — **받지 않는다**(호칭은 "연수생"; 입력 UI 가 크고 시연에 도움이 적다).
2. 질문 다섯이면 되는지 — **다섯 유지**, 다만 "차종" 은 시연 가치가 낮아 **뒤로 미루거나 뺀다**.
3. 답 형식 — **칩만**(숫자·자유 입력 없음: 운전석에서 키보드는 쓰지 않는다).
4. 언제 묻는지 — **첫 실행 때 한 번(건너뛰기 가능) + 홈 눈썹에서 언제든 수정**.
5. 저장 — **앱 내부 저장소 JSON 한 파일**(사내 에뮬 `adb root` 이라 접근 가능, 공개 저장소에 개인정보 없음). 초기화는 관리자 모드.
6. 관측 프로필을 운전자에게 보여줄지 — **보여 준다, 말로만**("연습이 쌓이고 있어요 · 약한 건 평행 주차") — 숫자는 리포트 자세히 보기에만.
7. 다중 운전자 — **이번엔 하나**. 모델은 목록을 받게 만들어 둔다.
8. 시연 시작 프로필 — **지금 시드(장롱 10년차·아이 등하원·주차 공포) 를 관리자 프리셋 "시연" 으로 고정**, 온보딩은 영상 1부 앞에 10초 컷으로 넣을지 결정.
9. 온보딩을 건너뛰면 — **기본값 = 지금 시드와 같은 "장롱" 프로필**이 아니라 **빈 프로필(초보 가정)** → 첫 과제 제안은 "출발 전 점검".
10. 프로필이 제안에 미치는 범위 — **과제 제안·멘트 말투·Copilot 프롬프트까지**, 채점 기준에는 영향 없음(공정성).

답을 주시면 P1 을 바로 시작한다(모델·저장·테스트, 화면은 시안 선택 뒤).
